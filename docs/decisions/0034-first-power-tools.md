# 0034. 첫 동력 시험 도구: 영점 명령과 시험 순서 실행 명령

- 상태: 채택
- 날짜: 2026-11-14

## 배경

- 팔을 뽑으면 베이스, 어깨, 위팔까지 먼저 조립해 위팔 끝에 추를 달고 어깨 서보가 버티는지와 온도를 본다 ([0028](0028-ur-style-joints.md)의 시험과 측정). 그 전에 관절마다 영점을 재야 하고(영점이 없는 관절은 움직이지 않는다, [0024](0024-servo-bus.md)), 실행 루프([0032](0032-run-loop.md))를 실제로 돌릴 명령이 있어야 한다.
- 영점 재는 절차는 0024의 영점에 있다: 영점 핀을 꽂고 핀 구멍의 틈을 정한 한쪽으로 밀어 붙인 채 토크를 끈 서보의 값을 읽고, 범위 가운데가 서보 값 2048 둘레에 오도록 위치 오프셋을 계산해 굽고, 다시 읽은 핀 자리의 서보 값과 오프셋과 방향을 로봇 설정에 적는다. 붙일 쪽과 방향을 아는 법은 정하지 않았다.
- 펜던트와 메시지([0033](0033-planning-and-simulation.md)의 만드는 순서 4)는 일이 크고, PC 없이 쓰는 단계에 필요하다. 첫 동력 시험은 그보다 먼저 온다.

## 검토한 대안

| 정할 것 | 대안 | 판단 |
|---|---|---|
| 방향을 아는 법 | 설계에서 계산 / 영점을 잴 때 잰다 | 잰다: 핀을 꽂기 전에 관절을 손으로 + 쪽으로 돌려 서보 값이 느는지 준다. 설계에서 계산하려면 서보가 어느 쪽으로 돌 때 값이 느는지를 따로 확인해야 하고, 조립 실수(서보를 뒤집어 넣음)를 잡지 못한다. 로봇 설정에 방향이 이미 있거나(다시 잴 때) `--direction`을 주면 재지 않는다 |
| 핀 구멍의 틈을 붙이는 쪽 | 관절마다 짐이 미는 쪽 / 늘 + 쪽 | 늘 + 쪽(관절 각이 느는 쪽): 관절마다 같은 말로 안내하고, 영점 오차(틈 0.05 mm면 약 ±0.07°)가 모든 관절에서 같은 쪽으로 나서 캘리브레이션이 한 번에 받는다 |
| 영점 값을 로봇 설정에 넣는 법 | 명령이 robot.toml을 고친다 / 명령은 세 줄을 내고 Claude가 옮긴다 | 세 줄을 낸다: robot.toml의 주석과 순서를 지키려면 TOML 편집 크레이트가 더 들고, 영점을 잴 때는 늘 Claude가 같이 있다. 굽기 전후의 덤프와 계산은 기록에 남는다 |
| 시험을 시키는 법 | 대화식 명령 줄 / 동작마다 명령 / 시험 순서 파일 | 시험 순서 파일(TOML): 멈춤(Enter를 기다림), 움직이기(관절 각), 버티기(초), 토크 끄기. 같은 시험을 그대로 다시 돌리고, 기록에 순서가 같이 남고, 시뮬레이션에서 먼저 돌려 볼 수 있다. 대화식은 사람이 그때그때 쳐야 하고, 동작마다 명령은 실행 루프를 끊었다 다시 세운다 |
| 돌리는 곳 | 파이 / PC | 처음에는 PC에 어댑터를 꽂고 돌린다 (맨 서보 확인과 같다, [0025](0025-controller-on-pi.md)). 파이 배포 명령과 실시간 설정([0026](0026-pi-runtime-deploy-records.md))은 컨트롤러를 파이에 올릴 때 붙인다. 버티기와 느린 움직임은 위치 서보가 스스로 잡고 있어서 PC의 박자 흔들림에 민감하지 않다 |

## 결정

- 영점 명령 `zero` (`crates/controller/src/zero.rs`): 한 번에 관절 하나.
  - `--yes`가 없으면 지금 서보 값, 위치 오프셋, 토크를 읽어 보이고 할 일을 말한다.
  - `--yes`가 있으면 순서대로 안내한다:
    1. (방향을 모르면) 핀을 빼고 관절을 + 쪽으로 20°쯤 돌린다. 100칸(약 9°) 넘게 움직여야 받는다.
    2. 핀을 꽂고 틈을 + 쪽으로 붙인 채 다섯 번 읽은 가운데 값을 쓴다.
    3. 위치 오프셋을 굽고, 다시 읽어 목표에서 한 칸 안인지 본다.
    4. 로봇 설정에 적을 세 줄을 낸다.
  - 토크가 켜져 있으면 하지 않는다. 사람이 Enter를 누르는 일이라 터미널 창에서만 돈다. 굽기 전후의 덤프를 `records/servo/`에 남긴다. 그다음 값 적용(`apply`)이 영점에서 계산한 각도 한계를 굽는다.
- 시험 순서 실행 명령 `run` (`crates/controller/src/runner.rs`):
  - 순서 파일의 관절만 켜서 실행 루프를 100 Hz로 돌린다. 이동 한계는 로봇 설정의 실행 루프 한계에 `speed_percent`를 곱한 값이다.
  - 버티기는 온도가 알림 기준에 닿으면 일찍 끝내고 다음 단계로 간다. 쉬는 기준에 닿아 실행 루프가 쉬기 시작하면 새 궤적을 받지 않아 팔을 내릴 수 없기 때문이다.
  - 움직이거나 버티는 동안 Enter를 누르면 감속해 서고 순서를 끝낸다. 고장이 나도 순서를 끝낸다. 끝나면 서보는 마지막 자리에서 버틴다 (0009).
  - 토크 끄기는 마지막 단계에만 둔다. 사람이 팔을 받쳤다는 멈춤 단계 뒤에 둔다. 실행 루프는 붙잡고 있거나 고장일 때만 토크를 끈다 (`release_all`).
  - `--yes`가 없으면 순서를 검사해 보이고 서보 상태만 읽는다. `--sim`이면 서보 대신 시뮬레이션 서버에 붙는다.
  - 박자마다 모드와 관절마다의 목표, 위치, 속도, 부하, 온도, 전압, 전류, 상태, 토크를 `records/run/`의 `samples.csv`에 남긴다. 단계와 알림은 `events.csv`에, 순서와 로봇 설정은 `meta.json`에 남긴다.
- 입력이 없는 곳에서 돌려도 실행 명령은 멈추지 않는다 (닫힌 표준 입력을 Enter로 보지 않는다). 멈춤 단계가 있는 순서는 터미널 창에서만 돈다.
- 시뮬레이션에 붙을 때는 토크를 켤 때의 EEPROM 견주기를 하지 않는다. 시뮬레이션은 메모리 표를 흉내 내지 않는다. 실물에서는 그대로 견준다 (0024).
- 영점을 잴 때 볼 3D 안내(관절마다 + 쪽 화살표, 핀 자리, 틈을 붙이는 쪽)와 첫 동력 시험의 순서 파일(추의 무게와 거는 자리, 버틸 각)은 팔을 조립할 때 만든다. 순서 파일의 값은 그때의 팔 계산으로 정한다 (0028).

## 근거

- 영점과 방향을 같은 자리에서 실물로 재면, 설계와 조립 사이의 어긋남(서보 방향, 핀 자리)이 로봇 설정에 들어가기 전에 드러난다. 다시 읽은 값이 목표에서 한 칸 안인지 보므로 핀이 빠지거나 틈이 반대로 붙은 것도 잡는다.
- 시험 순서를 파일로 두면 시험 자체가 기록이 되고, 실물 전에 시뮬레이션에서 같은 파일을 돌려 순서의 실수를 잡는다 (2026-11-14: 로봇 설정을 흉내 낸 j2, j3로 움직이기 → 버티기 → 돌아오기 → 토크 끄기를 시뮬레이션에서 끝까지 돌렸다).
- 버티기를 온도 알림 기준에서 끝내면, 쉬는 자세가 정해지기 전에도 뜨거워진 팔을 내린 뒤 쉬게 할 수 있다.
