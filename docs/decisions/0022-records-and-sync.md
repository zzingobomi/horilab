# 0022. 시험 기록과 PC 사이 데이터 넘기기

- 상태: 채택
- 날짜: 2026-11-10

## 배경

- 실물(서보, 카메라)은 PC 한 대에만 연결한다. 실물이 없는 PC에서도 작업한다.
- 그래서 일이 자주 이렇게 돈다: 실물이 있는 PC에서 시험한다 → 실물이 없는 PC에서 기록을 분석하고 고친다 → 실물이 있는 PC에서 다시 시험한다. 실물이 있는 PC에서 분석할 때도 있다.
- 이 흐름이 돌려면 기록만 보고 다른 PC에서 분석할 수 있어야 하고, 로그와 영상이 PC 사이를 쉽게 오가야 한다. 시험 영상도 찍어서 분석한다.
- 이전 프로젝트에서는 로그와 큰 파일을 구글 드라이브에 손으로 올리고 받았다. 매번 손으로 올리고, 받은 파일을 제자리에 옮겼다.
- 데이터는 그 데이터를 만드는 프로그램이 쓰는 자리(표준 경로)에 있어야 한다. 넘기기 편하자고 한 폴더에 몰아넣으면, 넘기는 방법이 데이터 구조를 정하게 된다.

## 검토한 대안

git에서 뺀 데이터(로그, 시험 기록, 영상)를 넘기는 방법이다. 코드, 문서, 작은 값 파일은 그대로 git으로 넘긴다.

| 대안 | 장점 | 단점 |
|---|---|---|
| 구글 드라이브에 손으로 올리고 받기 (이전 방식) | 설치할 것이 없다 | 매번 손이 간다. 받은 파일을 제자리에 두는 것도 손으로 한다 |
| 데이터만 담는 비공개 GitHub 레포 | PC마다 이미 있는 git과 로그인으로 된다. 이력이 남는다 | 파일 하나가 100 MB를 넘으면 받지 않아서 영상에 맞지 않는다. 큰 파일용 저장소(LFS)는 무료 용량이 작다 |
| Hugging Face 비공개 데이터셋 | 큰 파일과 이력을 다룬다. Python 패키지로만 다뤄서 PC에 설치할 것이 없다 | 계정과 토큰이 따로 필요하다. 무료 비공개 용량과, 작업하는 네트워크에서 접속되는지는 확인하지 않았다 |
| 구글 드라이브 PC 프로그램 (자동 동기화) | 손이 전혀 가지 않는다 | PC에 상주 프로그램을 설치해야 한다. 두 PC가 같은 파일을 보려면 데이터를 드라이브 폴더 안에 둬야 해서, 레포 안의 표준 경로와 맞추기 어렵다 |
| rclone + 구글 드라이브 | 명령 한 번으로 올리고 받는다. 큰 파일도 된다. 폰으로 찍은 영상을 드라이브 앱으로 바로 올린다. 실행 파일 하나라 레포 안에 둘 수 있다 | 구글 클라우드에 이 용도의 앱을 한 번 만들고, PC마다 한 번 구글 로그인을 허용해야 한다 (드라이브를 다루는 다른 프로그램도 앱이 필요하다). git 같은 이력은 남지 않는다. 무료 용량(15 GB)을 넘으면 비용이 든다 |

## 결정

rclone + 구글 드라이브로 한다.

- git에 있는 것(코드, 문서, 작은 값 파일)은 git으로 넘긴다. git에서 뺀 데이터 폴더(로그, 시험 기록, 영상)는 구글 드라이브의 `horilab/` 폴더 아래에 레포와 같은 경로로 비춘다. `build/`처럼 다시 만들 수 있는 것은 넘기지 않는다.
- 데이터는 종류마다 표준 경로에 둔다. 넘기는 방법 때문에 자리를 바꾸지 않는다.
- 레포에 동기화할 데이터 폴더 목록을 하나 둔다. 표준 경로를 정할 때마다 목록에 넣는다.
- 명령 한 번으로 올리고, 한 번으로 받는다. 새로 생기거나 바뀐 파일만 옮기고, 지우지 않는다. 받는 쪽 파일이 더 새것이면 덮어쓰지 않는다. 받을 때는 경로나 날짜로 고를 수 있게 한다. 오래된 데이터를 지우는 것은 따로 한다.
- Claude가 작업 흐름 안에서 돌린다. 실물이 있는 PC에서는 시험 순서의 마지막 단계로 올리고, 분석하는 PC에서는 분석을 시작할 때 받는다.
- 폰으로 찍은 영상은 드라이브 앱으로 드라이브의 영상 폴더에 올린다.
- rclone은 실행 파일과 설정을 레포 안의 git에서 뺀 폴더(`tools/local/`)에 두고, PC에 따로 설치하지 않는다. PC마다 한 번 브라우저로 구글 로그인을 허용한다. 모든 PC가 같은 권한(드라이브 읽기·쓰기)으로 로그인해서, 실물이 없는 PC에서도 올릴 수 있다.
- 로그인에는 직접 만든 구글 앱(OAuth 클라이언트, 데스크톱 앱)을 쓴다. rclone이 빌려주던 공용 앱은 2026년 중에 끝난다. 앱은 게시 상태로 둔다. 테스트 상태로 두면 로그인이 7일마다 풀린다. 게시에 필요한 홈페이지와 개인정보처리방침은 GitHub Pages 같은 무료 페이지에 둔다.

### 기록에 남길 것

- 실물 실행의 기록은 그것만 보고 다른 PC에서 분석할 수 있게 남긴다: 보낸 명령, 서보가 읽은 값(위치, 부하, 전압, 온도), 시각, 서보 설정(EEPROM), 코드 버전(git 커밋), 시험 조건(짐, 자세 등).
- 분석은 레포 안 스크립트로 한다. 그래서 어느 PC에서든 같은 경로로 같은 분석을 돌린다.
- 분석에서 나온 값 중 결정에 쓰는 것은 git(`data/measured.toml`, 문서)에 남기고, 어느 기록에서 나왔는지 같이 적는다.
- 같은 시험을 같은 조건으로 다시 돌리는 명령을 둔다. 고치기 전과 후를 비교하기 위해서다.

## 근거

- 영상까지 넘겨야 해서, 파일 크기 제한이 있는 GitHub는 맞지 않는다.
- 구글 드라이브는 이전 프로젝트에서 이미 썼고, 폰으로 찍은 영상을 바로 올릴 수 있다. 이전 방식에서 손이 가던 일(올리기, 받기, 제자리에 두기)은 rclone 명령이 맡는다.
- 레포와 같은 경로로 비추면 데이터를 표준 경로에 둔 채로 넘길 수 있고, 두 PC의 분석 스크립트가 같은 경로를 쓴다.
- 기록은 실행할 때마다 새로 생기는 파일이라 git 같은 이력이 필요한 일이 적다.
- rclone과 설정을 레포 안에 두면 PC에 따로 설치하지 않아도 된다.

## 영향

- 올리고 받는 명령은 `tools/sync.py`다 ([software.md](../software.md#시험-기록과-데이터)). 기록의 형식과 표준 경로(`records/`, `videos/`)는 [0024](0024-servo-bus.md)에서 정했고, 기록을 처음 만들 때 동기화 목록에 넣는다. 파이에서 생기는 기록은 파이가 직접 올린다 ([0026](0026-pi-runtime-deploy-records.md)). 첫 기록은 관절 하나 시험([joint-test.md](../joint-test.md))에서 나온다.
- 무료 용량(15 GB)이 모자라면 영상을 ffmpeg로 줄이거나 분석이 끝난 것을 정리한다. 용량을 늘리는 것은 비용이 들어 따로 정한다.
- 영상은 ffmpeg로 프레임을 뽑아 보거나 OpenCV로 마커 위치를 재서 분석한다. 카메라 고정이나 마커 같은 찍는 법은 영상이 필요할 때 정한다. ffmpeg도 PC에 설치하지 않고 레포 안(`tools/local/`)에 둔다.
- Claude의 메모는 PC마다 따로라서, 두 PC가 같이 알아야 할 것은 이 레포의 문서에 둔다.

## 바뀐 점

- 2026-11-10: 올리고 받는 명령(`tools/sync.py`)을 서보 연결 프로그램보다 먼저 만들었다. 데이터 형식과 상관없어서다. 실물이 없는 PC에서도 올릴 일이 있을 수 있어서, 읽기 전용 로그인을 빼고 모든 PC가 같은 권한으로 로그인한다. rclone 공용 구글 앱이 2026년 중에 끝나서 직접 만든 앱으로 로그인한다.
