# 0009. 제어 구조: 실행 루프와 안전

- 상태: 채택
- 날짜: 2026-11-07

## 배경

- 실물과 시뮬레이션을 같은 제어 코드로 움직인다 ([0001](0001-inherited-decisions.md)). 그러려면 제어 코드와, 서보나 MuJoCo를 실제로 움직이는 코드 사이의 경계를 정해야 한다.
- 모터 제어는 영상 처리와 다른 프로세스에서 돌고, PC와 파이 어디서든 같은 코드로 돌아야 한다 ([0005](0005-connection-architecture.md)).
- 서보는 위치 제어 서보다. 목표 위치를 주면 서보 안에서 위치를 맞춘다. 7개를 한 버스에서 동기 쓰기·읽기로 다룬다.
- 실물은 사람을 다치게 하거나 스스로 부서질 수 있다. 안전 기능은 나중에 덧붙이면 빠지는 곳이 생기므로 구조를 정할 때 자리를 정한다. 전원 차단 같은 물리적인 안전 규칙은 [hardware.md](../hardware.md#안전)에 있다.

## 검토한 대안

### 시뮬레이션과 실물을 바꿔 끼우는 자리

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 한 프로세스 안에서, 로봇 인터페이스 하나에 시뮬레이션 구현과 실물 구현을 둔다 | 가장 단순하다 | 서보 명령 주기가 같은 프로세스의 IK·계획 계산에 밀릴 수 있다. 모터 제어를 파이로 옮기려면 결국 프로세스를 나눠야 한다 |
| B. 모터 프로세스를 따로 두고, 상위 코드는 메시지로만 명령한다. 시뮬레이션과 실물은 모터 프로세스 안의 백엔드만 다르다 | 서보 명령 주기가 상위 코드와 상관없다. 같은 메시지가 PC 안에서도, 네트워크 너머 파이로도 간다. 안전 검사를 한곳에 모은다 | 메시지 형식을 정해야 하고 프로세스가 둘이다 |

### 상위 코드가 보내는 명령

| 대안 | 장점 | 단점 |
|---|---|---|
| 관절 목표를 주기마다 보낸다 (스트리밍) | 모터 프로세스가 단순하다 | 상위 코드나 네트워크가 늦으면 움직임이 끊긴다. 프로세스를 나눈 의미가 줄어든다 |
| 시간이 붙은 관절 궤적을 통째로 보낸다 | 모터 프로세스가 일정한 주기로 실행해서 상위 코드가 늦어도 움직임이 매끄럽다. 실행 전에 궤적 전체를 검사할 수 있다 | 궤적 형식과 실행 중 교체·정지 규칙을 정해야 한다 |
| 목표 자세만 보내고 서보가 알아서 간다 | 가장 단순하다 | 관절이 따로 움직여서 직선 이동 같은 협조 동작을 못 한다 |

## 결정

B로 하고, 명령은 시간이 붙은 관절 궤적이다. 따로 둔 프로세스는 로봇 옆 파이의 Rust 컨트롤러다 ([0023](0023-robot-controller.md), [0025](0025-controller-on-pi.md)).

```
[경로 계획: IK, 궤적]                       시뮬레이션이든 실물이든 같은 코드
     │  명령: 궤적, 정지, 토크 켜기·끄기
     │  상태: 관절 위치, 부하, 온도, 전압, 오류
     ▼  (컨트롤러 안에서, 또는 PC에서 WSS로. 0023)
[실행 루프 + 안전 검사 (컨트롤러)]           같은 코드 (Rust, 0025)
     ├─ 실물 백엔드: Feetech 서보 (동기 쓰기·읽기). 로봇 옆 컨트롤러 파이
     └─ 시뮬레이션 백엔드: MuJoCo (PC에서만)
```

- 경로 계획은 실행 루프하고만 이야기하고, 상대가 시뮬레이션인지 실물인지 모른다. 실물 백엔드는 명시적으로 켰을 때만 쓴다 ([0005](0005-connection-architecture.md)).
- 경로 계획 위에는 응용과 컨트롤러의 경계가 있다 ([0023](0023-robot-controller.md)). 작업 순서와 비전은 응용이 하고 이동 명령을 보낸다. 경로 계획은 컨트롤러 안에 있다 (팔 움직이기 단계에서는 PC에 있다, 0025).
- 실행 루프가 일정한 주기로 궤적을 따라 서보 목표를 보낸다. 조그처럼 바로바로 움직이는 동작은 짧은 궤적을 이어 보낸다.
- 관절은 번호가 아니라 이름으로 부른다 (MJCF와 같은 이름). 메시지와 코드 안의 단위는 rad와 s다. 서보 값(0~4095)과 rad 사이 변환(방향, 영점)은 실물 백엔드 안에서만 한다.
- 컨트롤러는 data/의 로봇 설정만 읽는다 (서보 ID·방향·영점, 소프트웨어 관절 한계, 속도 한계, 경고 기준, 관절 축과 링크 길이, 링크 충돌 도형). 설계 패키지, MuJoCo, 생성된 MJCF가 필요 없어서 파이에서도 그대로 돈다. 펜던트로 고치는 설치 설정(공구 끝점, 이름 붙은 좌표계, 안전 평면)은 컨트롤러가 따로 저장한다 ([0023](0023-robot-controller.md)의 1). 로봇 설정의 관절 이름, 관절 축과 링크 길이, 링크 충돌 도형이 MJCF와 같은지, 소프트웨어 관절 한계가 설계의 기계적 범위 안에 있는지는 PC의 테스트로 확인한다.
- 실행 루프와 안전 검사는 Rust 컨트롤러(`crates/controller`)에 있다. 시뮬레이션 백엔드도 이 실행 루프에 끼워서, 시뮬레이션에서도 실물과 같은 실행 루프와 안전 검사를 거친다. 붙이는 방법(Rust에서 MuJoCo C API를 부르기, 또는 Python MuJoCo가 서보를 흉내 내는 프로세스)은 [0025](0025-controller-on-pi.md)의 팔 움직이기 전에 정한다 ([0007](0007-repo-structure.md)).
- 실행 루프의 주기는 서보 7개로 잰 통신 시간을 보고 정한다 ([0008](0008-environment-and-packages.md)).

### 안전

안전 검사는 실행 루프에 둔다. 경로 계획도 계획할 때 미리 거르지만, 마지막 판단은 실행 루프가 한다. 서보로 가는 명령은 모두 여기를 지난다.

| 상황 | 처리 |
|---|---|
| 토크 켜기 | 사람이 명령할 때만 한다. 목표를 현재 위치로 맞추고 서보의 RAM 설정(토크 한도, 속도)을 쓴 뒤 토크를 켠다. 현재 위치에서 시작하는 궤적만 받는다 |
| 컨트롤러만 다시 켜짐 (서보 전원은 그대로: 배포, 되돌리기, 프로세스 죽음, 파이 재부팅) | 서보마다 토크 상태를 읽는다. 켜져 있으면 서보에 남은 목표와 설정을 그대로 이어받고 다시 쓰지 않는다. 현재 위치를 목표로 다시 쓰면 짐을 든 관절이 처진 만큼 한 번 더 내려가고(위치 서보는 짐이 있으면 목표보다 조금 아래에서 버틴다), 토크 한도를 낮추면 짐을 놓칠 수 있다. 꺼져 있으면 끈 채로 둔다. 끊기기 전의 궤적은 이어서 실행하지 않고, 움직임은 사람이 다시 명령해야 시작한다 |
| 서보 전원이 꺼졌다 켜짐 | 서보의 RAM 값(목표, 토크 한도, 속도)은 처음 값으로 돌아가므로 전에 쓴 값이 남아 있다고 보지 않는다. 컨트롤러가 돌던 중이면 아래 "서보 통신 오류"로 멈추고, 사람이 확인하고 풀면 위처럼 토크 상태를 읽어 다룬다. 전원이 돌아온 서보의 토크 상태는 관절 시험에서 실물로 확인한다 ([joint-test.md](../joint-test.md#순서)) |
| 관절·속도 한계 | 한계를 넘는 궤적은 실행 전에 통째로 거부한다. 잘라서 실행하지 않는다 |
| 자기 충돌, 안전 평면을 넘음 | 링크와 도구를 기본 도형으로 두고, 도형끼리와 안전 평면(책상 면 등, [0023](0023-robot-controller.md)의 1)까지의 거리를 본다. 닿는 궤적은 한계처럼 실행 전에 통째로 거부한다. 조그는 가까워지면 느려지다 그 앞에서 멈춘다. 바깥 물체는 응용이 피한다 |
| 경로 계획이 죽거나 조종하던 연결이 끊김 | 조종권을 풀고 감속해 그 자리에서 버틴다 ([0023](0023-robot-controller.md)의 3). 끊기기 전의 궤적은 이어서 실행하지 않는다 |
| 서보 통신 오류 | 읽기·쓰기 실패가 정해진 횟수를 넘으면 새 목표를 보내지 않고 오류 상태가 된다. 사람이 확인하고 풀기 전에는 움직이지 않는다 |
| 과부하, 과열, 전압 이상 | 부하·온도·전압을 주기적으로 읽고, 기준을 넘으면 멈추고 버틴 채 알린다. 토크를 끄면 팔이 떨어지므로 바로 끄지는 않는다. 서보 자체의 보호 설정(최대 토크 등)도 서보 준비 때 맞춘다 |
| 정지 | 소프트웨어 정지(멈추고 버티기)는 명령 하나로 한다. 최종 수단은 서보 전원 차단이다 ([hardware.md](../hardware.md#안전)). 전원과 로봇 사이의 스위치는 서보 전원 분배와 같이 정한다 |
| 컨트롤러와 서보 사이 통신이 끊김 | 소프트웨어로는 손쓸 수 없다. 위치 서보라 마지막 목표를 계속 잡고 있을 것으로 보고, 전원 차단으로 대응한다. 서보에 통신 감시 기능이 있는지는 레지스터 표로, 끊겼을 때 실제로 어떻게 되는지는 관절 시험에서 실물로 확인한다 |

- 기준값(한계, 실패 횟수, 부하·온도·전압 기준)은 로봇 설정에 두고, 서보와 연결 준비 단계(제작 로드맵 2단계)에서 정한다.

### 실물을 처음 움직이기 전에 통과할 시험

1. 시뮬레이션 백엔드로 경로 계획을 돌려 궤적 실행, 정지, 한계 거부를 확인한다 (자동 테스트).
2. 실물 백엔드의 오류 처리를 가짜 서보 버스로 시험한다 (응답 없음, 이상한 값).
3. 서보 7개를 연결해 한 주기(동기 쓰기 + 상태 동기 읽기)에 걸리는 시간과 흔들림을 잰다. 이 값으로 실행 루프 주기를 정한다.
4. 부하 시험: 컨트롤러 파이에서 컨트롤러를 돌리고, 카메라 파이와 PC에서 영상 처리를 돌린 채 몇 시간 동안 명령 간격과 통신 오류를 기록한다 ([0025](0025-controller-on-pi.md)).
5. 실물 첫 동작은 관절 하나, 낮은 토크 제한, 느린 속도로 시작한다.

## 근거

- 실행 루프를 따로 둔 프로세스(지금은 컨트롤러)에 두면 0005의 두 요구(영상 처리와 다른 프로세스, PC와 파이 어디서든)와 "같은 코드로 시뮬레이션과 실물"을 한 구조로 만족한다.
- 궤적을 통째로 보내면 상위 코드나 네트워크가 늦어도 움직임이 일정하다. ROS의 joint_trajectory_controller도 궤적을 받아 제어기 안에서 보간한다.
- 안전 검사를 서보 바로 앞 한곳에 두면, 상위 코드의 버그나 시험 스크립트가 보낸 명령도 빠짐없이 검사된다. 시뮬레이션도 같은 검사를 거치므로 안전 기능을 실물 없이 시험할 수 있다.
- 한계를 넘는 궤적을 자르지 않고 거부하는 건, 잘린 궤적은 계획한 것과 다른 움직임이 되기 때문이다.

## 영향

- 실행 루프와 안전 검사는 `crates/controller`에, 서보 버스는 `crates/servo`에 있다 ([0007](0007-repo-structure.md)).
- 메시지 형식과 궤적 형식(보간 방법, 실행 중 교체 규칙)은 [0023](0023-robot-controller.md)의 경계로, 만들 때 정한다.

## 바뀐 점

- 2026-11-10: 모터 프로세스는 Rust로 짜고 로봇 옆 컨트롤러 파이에서 돌린다 ([0025](0025-controller-on-pi.md)). 개발과 시뮬레이션은 PC에서 같은 프로그램으로 한다. 그래서 시뮬레이션 백엔드를 control 패키지(Python)에 두던 것을 모터 프로세스 안에 끼우는 것으로 바꿨고, 붙이는 방법은 0025의 팔 움직이기 전에 정한다. 부하 시험은 컨트롤러 파이에서 한다.
- 2026-11-10: 안전 표의 "시작, 재연결"을 셋으로 나눴다 (토크 켜기, 모터 프로세스만 다시 켜짐, 서보 전원이 꺼졌다 켜짐). 파이에서는 배포와 되돌리기 때마다 모터 프로세스가 다시 켜지는데([0026](0026-pi-runtime-deploy-records.md)), 그때마다 목표를 현재 위치로 다시 쓰면 짐을 든 관절이 내려가고, 서보 전원이 꺼졌다 켜진 뒤에는 서보에 쓴 값이 남지 않기 때문이다.
- 2026-11-11: [0023](0023-robot-controller.md)을 채택해 상위 제어 위에 응용과의 경계를 두고, 전송을 WSS로 정했다. 상위 제어나 조종하던 연결이 끊기면, 궤적을 끝까지 가던 것을 감속해 버티는 것으로 바꿨다. 끊긴 쪽의 명령을 사람 없이 끝까지 따르지 않게 하려는 것이다.
- 2026-11-11: 따로 둔 프로세스가 파이의 Rust 컨트롤러가 되어서([0023](0023-robot-controller.md), [0025](0025-controller-on-pi.md)), 결정·안전·시험에서 "모터 프로세스"를 "컨트롤러"(프로그램)와 "실행 루프"(그 안의 층)로, "상위 제어"를 "경로 계획"으로 바꿔 부른다. 검토한 대안과 지난 바뀐 점은 그때 이름 그대로 둔다.
- 2026-11-12: 안전 표에 자기 충돌과 안전 평면을 더했다 ([0023](0023-robot-controller.md)의 1). 그래서 컨트롤러가 읽는 로봇 설정에 관절 축과 링크 길이, 링크 충돌 도형이 들어간다. 안전 평면은 펜던트로 고치는 설치 설정에 둔다.
