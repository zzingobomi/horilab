# 0027. 범용 기준과 결정 다시 검토

- 상태: 제안
- 날짜: 2026-11-12

## 배경

- 호리봇은 한 대로 여러 작업을 하는 범용 팔이다 ([goals.md](../goals.md)). 랜덤 팔레타이징은 첫 작업일 뿐이다.
- 관절 범위가 합리적인지 따져 보다가, 앞선 결정 여러 개가 주로 박스 쌓기 자세(도구가 아래)와 몇 가지 시험 자세로만 평가된 것이 드러났다. "얼마나 되어야 하나"가 숫자로 없어서, 도구를 45° 기울이지 못하는 것 같은 한계를 기준 없이 받아들였다 ([0017](0017-skeleton.md)).
- 팔 부품을 그리기 전이라, 범용 기준을 정하고 결정을 처음부터 다시 검토한다. 기준은 UR3e로 정했다 (아래 기준).
  - 결정 기록을 세 묶음으로 나눠, 서로 모르는 검토자가 따로 읽었다: 기구(0003, 0011, 0013, 0015, 0017, 0019), 정밀도·시험·전원·서보(0012, 0016, 0021, 0024). 0015와 0021은 [0028](0028-ur-style-joints.md)로 바뀌어 지웠다, 작업·카메라·도구·컨트롤러(0001, 0014, 0018, 0020, 0023).
  - 큰 지적은 문서와 코드로 다시 확인했다: 옆에서 잡기 손계산, 기둥 자리, 원통 안쪽 반지름, J6 범위와 경계 규칙, 뒷면 혼 개수, 시험 짐 계산.
- 아래의 "어림"은 검토자의 손계산이고, 검토 코드로 다시 계산해 확인한다.

## 기준

견주는 기준은 UR3e다 (사용자, 2026-11-12, [goals.md](../goals.md)). UR3e에서 확인한 사실은 [references.md](../references.md#기준-모델-ur3e)에 있다. 아래는 정한 것과, 검토 코드를 만들며 정할 제안을 나눠 적는다.

### 자세와 동작: UR3e와 견준다 (정함)

- UR3e가 하는 자세와 동작은 호리봇도 한다. 못 하면 설계 탓인지 하드웨어 한계인지 가린다. 가리는 규칙은 [goals.md](../goals.md)에 있다.
- 비교 모델은 둘이다.
  - 원본 UR3e: 공식 치수 그대로다. 우리 모델이 공식 값과 맞는지 확인하는 데 쓴다.
  - 호리봇 크기 UR3e: 원본을 통째로 줄인 것이라 비율은 그대로다. 견주는 데 쓴다.
- 결과는 넷으로 나눈다.
  - 둘 다 됨: 호리봇이 지켜야 할 기본
  - UR3e만 됨: 까닭을 찾아 설계 탓인지 하드웨어 한계인지 가린다
  - 호리봇만 됨: 장점으로 적는다
  - 둘 다 안 됨: 시험 조건을 다시 본다

### 견주는 방법 (제안)

- 줄이는 비율: 위팔 + 아래팔 길이를 맞춘다 (400 / 456.75 mm = 0.876배).
- 양쪽에 같은 도구(평행 그리퍼, 같은 TCP)를 달고, 같은 책상 면 위에 둔다. 부딪힘은 형상으로 본다. UR3e는 UR이 공개한 충돌 형상을 쓴다.
- 자리는 지금 작업 영역(반지름 16~30 cm, 높이 2~18 cm)에 가두지 않는다. 안쪽 끝 16 cm도 팔꿈치가 정한 설계 한계였다. 베이스 가까이, 위, 뒤까지 넓게 놓고, 바깥 끝은 서보 토크로만 자른다.
- 도구 방향은 모든 방향을 고루 본다.
- IK 해는 양쪽 다 모두 허용하고, 어느 해로 됐는지 적는다. 작업 자세를 J5 > 0 하나로 정한 것([0013](0013-wrist-type.md))도 이 결과로 다시 본다.
- 관절 범위: UR3e는 공식 범위(팔꿈치 ±180°)로 둔다. 호리봇은 부품이 닿아 막히는 것과 서보 한 바퀴(경계 여유)로 막히는 것을 따로 센다. 앞은 설계 탓이고, 뒤는 하드웨어 한계 후보다.

### 하드웨어 기준: 호리봇의 값 (UR3e를 따르지 않는다)

| 항목 | 기준 | 상태 |
|---|---|---|
| 짐 | 평행 그리퍼(140 g) + 짐 150 g, 모든 자세에서 버팀 토크가 정격의 0.8배 안. 서보가 버티는 반지름(지금 어림 약 30 cm, [0017](0017-skeleton.md))은 이 계산으로 다시 낸다 | 정함 |
| 정밀도 | 도구가 아래일 때 수평 약 1 mm ([0012](0012-precision-metrics.md)) 그대로. 기울인 자세는 재서 기록 | 정함 |
| 전압과 열 | 움직일 때 전압이 처져도 서보 보호에 걸리지 않고, 덮개 안 서보와 부품이 무르는 온도 아래다. 숫자는 정해야 한다 | 제안 |
| 빠르기 | 목표 숫자가 없다. 정해야 한다 | 제안 |
| 쉬는 자세 | 브레이크가 없으니, 토크 없이 기대 둘 수 있는 접은 자세가 있다 | 제안 |

## 검토 결과

### UR3e와 견주기

`uv run python -m horilab_design.studies.ur_compare`로 다시 낸다. 원본 모델 확인은 `... ur_compare check`, 관절 구조가 막지 않는다는 가정은 `... ur_compare free`다.

- 비교 모델(UR3e)은 UR이 공개한 기구학과 충돌 형상으로 만들었다 (`studies/ur3e.py`). 공개 모형과 링크 자리가 같고(차이 1e-15 m 이하), 관절 각 0의 플랜지 위치가 DH 값과 같다.
- UR3e 공개 형상으로는 팔을 세운 자세에서 팔꿈치가 약 155°(손목 자세에 따라 157°)까지 접히고, 그다음 손목 1이 위팔에 닿는다. 나머지 관절은 막힘 없이 돈다. 호리봇 팔꿈치는 약 122°에서 닿는다.
- 시험 자세는 14,196개다.
  - TCP 자리 169곳: 반지름 0~48 cm, 높이 2~50 cm, 4 cm 간격
  - 도구 방향 42개: 아래부터 위까지 30°마다, 기울이는 방향 8개
  - 도구 돌림 2개
  - 두 팔에 같은 평행 그리퍼를 달고, IK 해는 모두 본다. 호리봇 J1은 서보 한 바퀴의 경계 여유 때문에 ±135°로 둔다.

| 갈래 | 자세 수 |
|---|---|
| 둘 다 됨 | 2,044 |
| UR3e만 됨 | 4,319 |
| 호리봇만 됨 | 116 |
| 둘 다 안 됨 | 7,717 |

- UR3e가 되는 자세 6,363개 중 호리봇이 되는 것은 32%다. 도구 방향별로 보면 아래 62%, 30° 기울임 29~69%, 수평 10~49%, 위쪽(120° 이상) 0~42%다.
- UR3e만 되는 자세에서 호리봇이 못 하는 까닭 (자세 수). 오른쪽 열은 관절 구조가 막지 않는다고 가정한 값이다: 서보와 자기 브래킷이 닿는 것을 세지 않고, 관절 범위는 지금 가운데에서 ±135°로 둔다.

| 까닭 | 지금 | 관절 구조가 막지 않으면 |
|---|---|---|
| 관절 구조: 서보가 자기 관절의 브래킷에 닿음 (설계) | 2,709 (J4 1,119, J6 747, J5 445, J3 363) | 0 |
| 지금 관절 범위: 270° 안이지만 지금 범위 밖 (설계) | 725 (J4 453, J3 122) | 0 |
| 부딪힘: 다른 부품끼리, 책상 (설계) | 515 (J3 집 ↔ 아래팔 195, J1 몸통 ↔ 위팔 146, 위팔·아래팔 ↔ 도구 90) | 232 (J3 집 ↔ 아래팔 146) |
| 한 바퀴: 270°보다 더 돌아야 함 (하드웨어 후보) | 74 (J1) | 893 (J4 395, J5 296, J3 82, J1 73) |
| 토크: 정격의 0.8배를 넘음 (하드웨어) | 218 (J3 196, J2 22) | 697 (J3 415, J2 282) |
| 못 닿음: IK 해가 없음 | 78 | 78 |
| UR3e가 되는 자세 중 호리봇이 되는 비율 | 32% | 70% |

- 가장 큰 차이는 관절 구조다 (설계). ㄷ자 브래킷이 서보를 감싸서 관절마다 약 180~220°만 돈다 (처음 관절 구조, 지금은 [0028](0028-ur-style-joints.md)). UR3e는 관절이 한 바퀴 넘게 돈다.
- 관절 구조가 막지 않아도 남는 차이는 서보 한 바퀴(UR3e가 되는 자세의 14%)와 토크(11%)가 크다. 둘 다 하드웨어 후보다. 한 바퀴는 여러 바퀴 모드 같은 방법이 되는지 확인해야 하드웨어 한계로 정할 수 있다 (아래 3). 설계로 남는 것은 팔꿈치 접힘(J3 집 ↔ 아래팔)이 크다.
- 호리봇만 되는 자세는 대부분(101개) 줄인 UR3e가 IK 해가 없는 자세다. UR형 팔은 손목 중심(J5·J6 축이 만나는 점)이 베이스 축에 옆 오프셋보다 가까이 올 수 없다. 줄인 UR3e는 옆 오프셋이 11.5 cm로 호리봇(6.3 cm)보다 길다.
- 한계: 호리봇 형상은 상자와 원기둥으로 만든 개념 형상이다 (커넥터, 선, 볼트 머리 없음). 한 방위만 봤고 간격은 4 cm, 30°다. 관절 구조 가정은 지금 형상에서 브래킷 닿음만 뺀 값이다. 관절 구조를 실제로 바꾸면 형상도 바뀐다.

### 관절 구조 대안: UR식 관절 (개념)

`uv run python -m horilab_design.studies.ur_joints`로 견준다 (관절 범위 ±165°). `... ur_joints 135`는 ±135°이고, 치수와 도는 범위는 `... ur_joints check`다.

- 구조: 부모 링크의 원통(집)이 서보를 품는다. 자식 링크는 출력 쪽 뚜껑으로만 잇는다.
  - 뚜껑은 출력 혼에 볼트로 묶고, 출력 면 베어링(STS 관절 6806, 어깨 6808)의 안쪽 링에 앉는다. 굽힘은 베어링이 받는다.
  - 뒷면 혼은 쓰지 않는다. 서보 뒷면에 꽂는 커넥터와 선 자리는 집 안에 둔다.
  - 부모와 자식이 축 방향으로 비켜 있어서 서로 닿지 않고 돈다. UR3e와 같은 짜임이다.
- 개념 치수:
  - 원통 지름: STS 관절 49 mm, 어깨 59 mm
  - J1 축을 지나는 면에서 옆으로: 위팔 관 58 mm, 아래팔 관 11 mm
  - d4 67, d5 71, d6 31 mm (지금 63 · 63 · 50). 링크 길이는 0017 그대로다.
- 팔을 세운 자세에서 J1, J4, J6는 막힘 없이 한 바퀴 돈다. J3는 -133° ~ +156°(UR3e 약 155°), J2는 ±137°(위팔이 J1 몸통에 닿음)다.
- J2가 드는 무게는 1,092 g으로 지금(969 g)보다 123 g 무겁다. 베어링과 닫힌 원통 몫이다.

| UR3e가 되는 자세 6,363개 중 | 지금 설계 | UR식 관절 ±135° | UR식 관절 ±165° |
|---|---|---|---|
| 호리봇이 되는 비율 | 32% | 69% | 75% |
| 설계 탓 (관절 구조, 지금 범위, 부딪힘) | 3,949 | 3 | 3 |
| 서보가 허락하는 범위보다 더 돌아야 함 | 74 | 504 | 58 |
| 토크: 정격의 0.8배를 넘음 | 218 | 1,419 | 1,431 |
| IK 해 없음 | 78 | 74 | 74 |
| 호리봇만 되는 자세 | 116 | 1,121 | 1,309 |

- UR식 관절이면 설계 탓으로 못 하는 자세가 거의 없어진다. 남는 차이는 대부분 토크다(±165°에서 J2 994, J3 437). 반지름 약 32 cm 밖에서 서보가 짐을 버티지 못하는 하드웨어 한계다.
- ±165°는 관절마다 기계 멈춤을 두고, 서보 한 바퀴의 0/4095 경계를 멈춤 밖 30° 안에 두는 경우다. 지금 경계 규칙(0024: 소프트 한계 밖 45°)대로면 ±135°이고, 서보 범위에 막히는 자세가 504개다. 기계 멈춤이 있으면 손으로 밀어도 경계를 넘지 않으므로, 규칙을 고칠 수 있는지 따진다.
- 같은 급 서보(STS3215 급)로 만든 UR형 팔 myCobot 280은 관절마다 ±140~168°(J6 ±180°)를 쓰고, 손목 오프셋(64.6 · 73.2 · 45.6 mm)과 관절 집 지름(48 mm)이 이 개념과 비슷하다 ([references.md](../references.md#참고한-팔)). 팔 길이는 우리의 약 절반이다.

#### 관절을 지나는 선

- 지나는 선: 서보 선은 서보 줄을 둘로 나누므로(0016) J1에 2가닥(J1 → J2, 어댑터 → J3), J2~J6에 1가닥씩 지나간다. D405 USB 3 선은 J5~J1, 나중에 흡착 관이 J6~J1을 지나간다.
- UR식 관절은 서보가 축 가운데에 있어서 선이 가운데로 지나가지 못한다. 관절마다 선이 축을 감으며 ±165°를 견딜 칸이 필요하다.

| 후보 | 필요한 공간 | 판단 |
|---|---|---|
| 태엽(나선): 바깥 끝은 부모, 안쪽 끝은 자식에 묶는다 | 감아 둘 선 길이 ≥ 회전각 ÷ (1/안쪽 반지름 - 1/바깥 반지름) | 베어링 둘레(안쪽 반지름 22 mm, 바깥 28 mm)에 두면 약 590 mm라 맞지 않는다. 안지름이 큰 베어링 안쪽(12~19 mm)에 두면 약 190 mm다 |
| U자 고리 칸: 부모 고리 벽과 자식 허브 사이에서 U자로 꺾인 선이 굴러간다 | 칸 폭이 굽힘 반지름의 2배에 틈을 더한 값. 납작한 선(굽힘 반지름 약 5 mm)이면 폭 약 12 mm, 높이 약 5 mm | 원통 지름이 약 12 mm, 관절이 축 방향으로 약 6 mm 커진다. 둥근 선(지름 2.5~3 mm)이면 폭이 약 25 mm라 맞지 않는다 |
| 원통 둘레 나선 감기 | 3바퀴면 반지름이 -13%~+18% 변해 반지름 약 8.5 mm 여유, 축 방향 약 9 mm | 덮개가 커진다 |
| 바깥 고리 | 없음 | 관절마다 고리가 겉으로 보인다. 고른 안이다 (아래 네 안 견주기) |

- 개념 형상에 U자 고리 칸 예산(원통 반지름 +6 mm, 베어링과 뚜껑 사이 +6 mm)을 넣어 견줬다 (`... ur_joints cable`, 치수는 `... ur_joints check cable`).
  - STS 관절 원통 지름 61 mm, d4 79 · d5 77 · d6 37 mm, J2가 드는 무게 1,199 g이다.
  - UR3e가 되는 자세 중 67%가 된다 (예산 없이 75%). 줄어든 것은 거의 토크다: 토크에 막히는 자세가 1,431개에서 1,982개(J2 1,407, J3 575)로 늘었다. 남는 차이의 93%가 토크라서, 관절이 가벼울수록 통과율이 오른다.
- D405 USB 3 선은 움직이는 고리 반지름이 40 mm 이상이어야 해서([design.md](../design.md#d405-케이블)) 관절 안 칸에 들어가지 않는다. 팔 바깥을 따라 관절마다 여유 고리를 두고 링크에 묶는 길이 남는다.
- 서보 선은 바깥 고리로 정했다 (아래 네 안 견주기). 고리는 설계에서 정하고 조립하며 본다:
  - 고리를 둘 쪽과 길이: 팔을 접은 자세에서 링크 사이에 끼지 않게, 검토 형상에 고리 부피를 넣어 본다.
  - 선이 집을 나가고 링크로 들어가는 자리: 커넥터를 구멍에 꿰지 않게 홈에 눕혀 넣고, 둥글게 받쳐 묶어 급히 꺾이지 않게 한다.
  - 선 길이가 고리만큼 길어진다. 산 선(30 cm, 90 cm, [부품표](../bom.md))으로 되는지 배선을 그리며 센다.
  - 조립할 때 서보 힘 없이 손으로 양 끝 멈춤까지 돌려 고리가 걸리지 않는지 본다.

덮개 없이 서보가 드러난 ㄷ자 브래킷(노출형)도 같은 시험으로 쟀다 (`... ur_compare bare`).

- 사용자: 관절 구조는 UR식으로 바꾸는 쪽이다 (2026-11-12). 선은 C로 정했다 (2026-11-12): 관절에서 선이 조금 보이는 것은 괜찮고, 조립이 쉬운 쪽을 고른다. 베어링은 NSK 깊은 홈(6806ZZ 4개, 6808ZZ 1개)으로 정해 주문했다 (2026-11-12, [부품표](../bom.md)). 나머지 살 것은 설계가 굳은 뒤 팔 전체 목록으로 한 번에 정한다. 관절 구조와 시험 계획은 [0028](0028-ur-style-joints.md)로 정했다.
- C가 조립이 쉬운 까닭: 관절마다 서보에 선을 꽂고, 집 옆 홈에 눕혀 빼고, 고리를 남겨 양쪽을 묶으면 끝난다. 산 완제품 선을 그대로 쓰고, 고리는 다 조립한 뒤에도 보고 고칠 수 있다. D는 납작한 선이 따로 필요할 수 있고, 뚜껑을 닫기 전에 선을 칸에 U자로 눕혀야 하며, 닫으면 보이지 않아 걸리면 관절을 다시 풀어야 한다.

### 큰 문제 (조립 뒤에 알면 비싼 순서)

1. **관절 구조와 골격이 UR3e 기준을 못 채운다.**
   - UR3e(호리봇 크기)가 되는 자세 가운데 호리봇은 32%만 된다 (위 견주기).
   - 가장 큰 까닭은 처음 관절 구조였다 (지금은 [0028](0028-ur-style-joints.md)). 관절이 약 180~220°만 돌아서 UR3e만 되는 자세의 63%가 막힌다. 관절 구조가 막지 않으면 70%가 된다.
   - 그다음 설계 문제는 지금 관절 범위(17%)와 팔꿈치 접힘이다. 팔꿈치는 위팔과 한 면이라 약 122°에서 닿고, UR3e는 아래팔이 위팔 옆을 지나 약 155°까지 접힌다. 0017에서 버린 "아래팔을 옆으로 비켜 다는" 안(UR3e의 구조, [references.md](../references.md#기준-모델-ur3e))이 후보다.
   - 처음 기준안의 "반지름 20~28 cm에서 도구를 수평 바깥으로 두고 옆에서 잡기"는 UR3e로도 안 된다. 그리퍼가 길어서 손목 중심이 베이스 축에 옆 오프셋보다 가까이 와야 하기 때문이다 (반지름 약 30 cm 안). 기준을 UR3e와 견주는 것으로 바꾸면서 이 기준안은 뺐다.
2. **케이블과 관이 지나갈 길이 형상에 없다.**
   - 원통 안에는 브래킷과 2 mm 틈뿐이다. D405 USB 3 선은 움직이는 고리 반지름이 약 40 mm 필요하다.
   - 넘어야 할 것: D405 선(J1~J5), 서보 줄(단자 2 줄은 J1·J2), 그리퍼 선(J6), 나중의 흡착 관(J1~J6).
   - J1과 J6를 UR3e처럼 많이 돌리려면 선이 감길 자리가 필요하다. 다음 설계 대상인 J1 베이스에 이 자리가 없다.
   - 원통 안에 넣으면 원통과 손목 오프셋이 커지고, 밖으로 내면 겉으로 보인다. UR식 관절에서는 서보 선을 관절 바깥 고리로 내기로 하고 외형 목표([goals.md](../goals.md))를 고쳤다 (위 네 안 견주기).
3. **회전 범위와 서보 한 바퀴.**
   - UR3e는 플랜지가 끝없이 돌고 나머지 관절은 ±360°다 (팔꿈치는 몸에 막혀 약 ±180°).
   - 호리봇은 경계 여유 45°를 모든 관절에 두면 범위가 270° 미만이어야 한다. 그래서 지금의 J1 ±175°도 로봇 설정에 넣을 수 없다. 관절마다 기계 멈춤과 경계 여유를 정한다.
   - 관절 구조가 막지 않아도, UR3e가 되는 자세의 14%는 270°보다 더 돌아야 한다 (J4, J5가 많다, 위 견주기).
   - 위치 모드가 0/4095 경계를 넘는지, 여러 바퀴 모드(스텝 모드)가 되는지는 실물로 확인하지 않았다. 이것으로 넓힐 수 있으면 한 바퀴는 하드웨어 한계가 아니다.
4. **토크, 전원, 열의 여유를 도구가 아래인 자세로만 봤다.**
   - 기울인 자세에서 어깨가 0.8배를 넘을 수 있다(어림). 짐의 무게중심을 TCP 한 점에 두었다.
   - 견주기에서 버팀 토크에 막히는 자세는 지금 218개, 관절 구조가 막지 않으면 697개(UR3e가 되는 자세의 11%)다. 대부분 팔꿈치(J3, STS3250)이고, 그다음이 어깨(J2)다.
   - 움직일 때 전압이 처지면 서보가 스스로 힘을 빼서 팔이 떨어질 수 있다. 과열 보호(STS3215 70°C, STS3250 80°C)는 PLA가 무르는 온도(55~60°C)보다 높다.
   - STS3215는 덮개(원통) 안에서 열을 잰 적이 없다.
5. **카메라 기둥이 손목이 닿는 자리에 있다.**
   - 맞은편 모서리 기둥(중심 26.5, ±25.5 cm)은 TCP 반지름 약 25.5 cm 밖, 기둥 방위 둘레에서 도구가 아래인 자세도 막는다(어림). 0018은 방위 0° 자세로만 봤다.
   - 컨트롤러는 기둥을 모른다. 조그하다 부딪히면 기둥 카메라 캘리브레이션이 틀어진다.
6. **관절 하나 시험이 범용 팔에 맞는지.**
   - 합격선이 없다. 시험 토크가 적힌 값(정격 0.73배)보다 작다(약 0.62배, 어림). STS3215 관절은 다른 서보인데 이 결과를 그대로 쓴다.
   - 팔꿈치 구조가 바뀌면 시험할 대상도 바뀐다. 서보 쪽 측정(처짐, 틈, 열, 통신 끊김)은 구조가 바뀌어도 쓸모 있다.

### 그 밖에 찾은 것

- **기구**
  - 관과 서보 집에 돌아가는 것을 막는 맞춤(키, D자 면)이 없다. 손으로 각도를 맞추면 J2·J3·J4가 평행에서 틀어진다(1°면 끝에서 약 4 mm).
  - 관을 뽑는 방향이 정해지지 않았고, 출력 규칙끼리 부딪힌다.
  - 부딪힘 검사 형상에 커넥터, 꽂은 선, 볼트 머리가 없다 ([design.md](../design.md#출력-전-확인)의 규칙과 어긋남).
  - J1을 쌓은 높이를 서보 몸통으로만 셌다. 뒷면 돌기와 꽂은 커넥터(약 3 mm 더)와 선이 나갈 길이 빠졌다.
  - 휨 계산에 손목(목, J5·J6 고리, D405 받침판)이 없다.
  - 서보를 갈아 끼울 수 있는지: J1은 베이스 밑을 열어야 하고, J3는 출력 원판을 떼면 영점을 다시 잡아야 한다.
  - 관절마다 부딪히기 전까지의 범위를 한 바퀴 전체로 다시 낸다 (J3 음의 방향 포함). 지금 값은 상자 링크와 한 자세로 낸 것이다.
- **정밀도와 시험**
  - 기울인 자세를 재려면 포인터 끝을 구(기준 구)로 하는 안을 정한다. 여러 방향 접근, 포인터 끝 벗어남, 직선 경로 벗어남도 재서 기록한다.
  - 상대 정확도 목표는 관절 하나 결과만으로 정할 수 없다. 오차 예산(링크 길이, 핀 틈, J1 기울기, 처짐)을 세운다.
  - 관절 시험에 I 게인과 적분 한계, 움직이는 단계(봉우리 전류, 전압 바닥), UR 오프셋이 만드는 비틀림, 관절을 지나는 케이블의 스프링 효과를 넣을지 정한다.
  - 영점 핀 구멍의 틈 0.05 mm는 잰 값이 아니다.
- **전원과 서보**
  - 서보 보호(전압·과열·과전류·과부하에서 힘을 뺌)와 "멈추고 버티기"(0009)가 맞물리면 결국 팔이 떨어진다. 과열·과부하 때는 쉬는 자세로 내려놓는 대응을 정한다.
  - 최대 토크가 100%라 부딪히면 PLA 부품이 부러질 수 있다. 관절마다 토크 제한을 정한다.
  - 최대 입력 전압이 사양 상한보다 높게 잡혀 있다 (STS3250 16.0 V).
  - 과부하 칸 셋은 로봇 설정에 없어 메모리 표 초기값으로 맞춘다. 첫 덤프와 같지만 robot.toml의 주석과 맞지 않는다.
  - + 플러그를 뽑아도 어댑터의 USB 전기로 서보가 살아 있는지 확인한다.
  - 비상 정지(전원 차단)는 팔이 떨어진다. 차단 전에 내리는 단계를 컨트롤 박스 릴레이와 같이 정한다.
- **카메라와 작업**
  - D405 볼트 길이가 한계에 딱 맞는다 (받침판 6 mm + 나사 깊이 4 mm = M3 × 10).
  - D405 형상 모형은 카메라 상자를 기울이지 않았고, 플러그와 굽힌 선이 없다.
  - 그리퍼의 잡을 물체(크기, 무게)와 열림 폭이 숫자로 없다. 구멍 잡기용과 일반용 손가락 끝을 나누는 안을 권한다.
  - 둘레 장비(가변 전원, 파이, 컨트롤 박스)가 팔이 쓸고 지나가는 자리에 있을 수 있다. 책상 뒤가 벽인지 모른다.
  - 기둥 카메라의 바깥 캘리브레이션 값을 설치 설정에 둘 만하다.
- **문서끼리 어긋난 곳**
  - 0001의 낡은 행, 0003과 design.md(자석·스냅), 0020의 짐(150 g과 코드의 100 g), 서보 커넥터 자리(사진 어림 9~16 mm와 "10 mm부터"), 0026의 "서보는 토크가 꺼진 채 켜진다"(확인 전).

### 실물로 미리 확인할 것 (팔을 설계하기 전 탁상 시험)

이 가운데 서보 동작은 맨 서보 확인으로 묶고, 열은 다 만든 팔에서 잰다 ([0028](0028-ur-style-joints.md)).

- 예비 STS3215(ID 20)로, 아무것도 달지 않고 (맨 서보 확인):
  - 위치 모드가 0/4095 경계를 넘는지, 여러 바퀴 모드가 되는지
  - 각도 한계 밖 목표를 어떻게 하는지
  - 보호에 걸릴 때 힘을 완전히 빼는지, 버티는 토크로 버티는지, 다시 풀리는 조건
  - 현재 전류의 부호와 눈금
- 원통 안에서 버틸 때의 서보 온도(ST-3120, STS3215)는 다 만든 팔에서 잰다. 그전에는 떼어 낼 수 있는 뒷면 덮개와 온도를 보다가 쉬는 자세로 내리는 컨트롤러로 대비한다.
- 서보 뒷면 커넥터 자리와 STS3215 뒷면 돌기 지름을 캘리퍼스로 잰다.
- + 플러그를 뺀 채 서보가 응답하는지 본다.

## 결정 (제안)

1. 기준은 UR3e로 정했다 (위). 견주는 방법의 제안 값은 검토 코드를 만들며 정한다.
2. 비교 모델 둘(원본 UR3e, 호리봇 크기 UR3e)과 같은 자세 시험을 만들었다 (위 견주기). 검토 코드에 남은 일:
   - 짐의 무게중심을 TCP보다 도구 축으로 앞에 둔다.
   - 형상에 커넥터, 꽂은 선, 볼트 머리를 넣는다.
   - 카메라 기둥 후보를 모든 방위와 시험 자세로 본다.
3. 관절 구조는 UR식으로 정했다 ([0028](0028-ur-style-joints.md)). 견주기에서 가장 큰 차이였다 (32% → 75%). 세부는 팔을 다시 설계하며 정한다:
     - 관절마다 선 고리의 자리와 길이, D405 선
     - 조립 순서와 서보 고정
     - 기계 멈춤과 0024 경계 규칙
     - J1 베이스 (스프링 자리)
4. 골격을 UR식 관절로 다시 고른다. 링크 길이, 옆 오프셋, 도구 길이를 같은 시험으로 보고, 토크(하드웨어 한계)가 막는 자리를 숫자로 적는다. 팔꿈치 옆 오프셋은 UR식 관절에서 저절로 생긴다.
5. 서보 한 바퀴(270°)가 하드웨어 한계인지 맨 서보 확인에서 본다 (위치 모드의 경계, 여러 바퀴 모드, 0028).
6. 케이블 길과 베이스·원통 부피 예산을 관절 구조, 골격과 같이 정한다.
7. 결과로 0011~0024를 고친다. 관절 하나 시험은 하지 않는다 (0028).

## 근거

- 팔 부품을 하나도 그리지 않은 지금 고치면, 다시 할 일은 계산과 시험 부품 몇 개다. 조립 뒤에 알면 팔 전체를 다시 그리고 뽑아야 한다.
- 기준이 있어야 검토 결과를 통과와 실패로 말할 수 있다. 이번 일은 기준이 없어서 생겼다.
- UR3e와 견주면 통과와 실패를 실제 협동로봇이 하는 일로 가린다. 임의로 고른 숫자(45° 8방향 등)는 범용 팔에 맞는지 근거가 없다.
- UR3e는 UR 가운데 가장 작은 책상용 모델이다. 위팔과 아래팔이 호리봇의 1.1~1.2배라 크기가 가깝고, 외형도 UR식으로 정했다 ([0019](0019-ur-look.md)).

## 영향

- J1 베이스와 손목 부품은 UR식 관절로 다시 설계한다 (0028).
- 컨트롤러 만드는 순서 4~5번(0024)을 다시 한다. 5번은 맨 서보 확인 명령이 됐다.
- 산 부품과 소프트웨어는 그대로 쓴다. 이미 뽑은 J3 시험 부품(0021)은 ㄷ자 브래킷 구조라 쓰지 않는다 (0028).
- 출력 전 확인([design.md](../design.md#출력-전-확인))에 UR3e 비교 시험과 하드웨어 기준 검사를 넣고, 큰 부품을 뽑기 전에는 독립 검토를 한 번 더 한다. 이것은 견주는 방법을 정할 때 같이 적는다.
