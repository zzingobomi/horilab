# 0001. 설계 브리프에서 이어받은 결정

- 상태: 채택 (체결 항목은 [0003](0003-fastening-nut-traps.md)으로, 모터 배치는 [0011](0011-joint-drives.md)로, 손목 형식과 D405 자리는 [0013](0013-wrist-type.md)으로, 양쪽 지지 관절은 [0028](0028-ur-style-joints.md)로 대체됨)
- 날짜: 2026-11-06

## 배경

이 레포를 시작하기 전에 설계 브리프 한 장으로 방향을 정했다. 그 결정들을 다시 따지지 않고 근거와 함께 옮겨 둔다. 브리프 단계에서 한 결정이라 대안 비교는 아래에 적은 만큼만 남아 있다.

## 결정과 근거

| 결정 | 근거 | 지금 내용 |
|---|---|---|
| 사지 않고 직접 만든다 | 100만 원대 서보 팔은 같은 정밀도 문제가 남고, BLDC+감속기 팔은 예산 밖이다 | [background.md](../background.md) |
| ~~모터는 Feetech STS (어깨 STS3250, 나머지 STS3215)~~ | ~~이미 가지고 있고, 7개로 6축과 그리퍼가 나오며 모두 한 버스에 물린다~~ | [0011](0011-joint-drives.md)로 대체 (어깨 ST-3120, 팔꿈치 STS3250, 모두 한 버스) |
| Dynamixel은 섞지 않는다 | 섞으면 버스와 전원(XL330은 5V)이 둘로 갈라진다. 가진 XL430·XL330은 STS3215보다 약하다. 품질이 확실히 나은 XM430급은 개당 약 $270이라 6축이면 모터값만으로 로봇 한 대 값이다 | [design.md](../design.md) |
| 설계는 코드 CAD(build123d)와 OCP CAD Viewer로 한다 | 치수 값 하나에서 모든 결과물을 뽑을 수 있다. OpenCascade 커널이라 원하는 모서리 필렛, STEP/STL/3MF 내보내기, 조인트 조립이 된다 | [software.md](../software.md) |
| 치수 값 하나에서 부품·조립 화면·URDF·MJCF·부품표·계산을 뽑는다 | 이전 프로젝트는 CAD에서 뽑은 URDF와 실물이 어긋났다 | [software.md](../software.md) |
| 정밀도는 설계로 잡는다 (짧은 손목, ~~양쪽 지지 관절~~, 마스터링 핀, 상자 단면 링크) | 이전 프로젝트는 캘리브레이션으로 오차를 더 내릴 수 없었다 | [design.md](../design.md). 관절은 출력 면 베어링이 굽힘을 받는 UR식으로 대체 ([0028](0028-ur-style-joints.md)) |
| ~~나사는 플라스틱에 직접 박지 않고 열 인서트를 쓴다~~ | ~~PLA 크리프와 URDF 불일치 대책~~ | [0003](0003-fastening-nut-traps.md)으로 대체 |
| ~~손목은 가능하면 구형(롤-피치-롤), 어려우면 오프셋 작은 UR형~~ | ~~구형 손목은 위치와 자세를 따로 풀 수 있다~~ | [0013](0013-wrist-type.md)으로 대체 (UR형) |
| 손목 끝 표준 플랜지로 그리퍼를 바꿔 달고, ~~D405는 로봇 쪽 플랜지에 단다~~ | 다시 끼워도 TCP가 유지되고, 그리퍼를 바꿔도 hand-eye 캘리브레이션이 유지된다 | [design.md](../design.md). D405 자리는 [0013](0013-wrist-type.md)으로 대체 (J6 앞 손목 하우징) |
| 첫 도구는 캘리브레이션 포인터, 첫 그리퍼는 흡착, 두 번째는 평행 그리퍼 | 포인터로 플랜지 재현성을 싸게 확인한다. 박스를 붙여 쌓으려면 흡착이 맞다. 평행 그리퍼는 열고 닫아도 TCP가 안 움직이고 파지 검출 모델과 맞는다 | [design.md](../design.md) |
| MuJoCo로 출력 전에 검증한다 | 손목 문제 같은 설계 실수를 만들기 전에 잡는다 | [software.md](../software.md) |
| Windows 네이티브에서 개발한다 (WSL 아님) | USB 장치(서보, D405)가 바로 잡히고 뷰어가 GPU로 바로 그린다 | [software.md](../software.md) |
| 소프트웨어는 Python으로 시작하고, React(R3F)는 실물 단계에서 필요하면 붙인다 | 설계, 시뮬레이션, 제어를 한 언어로 묶어 같은 코드를 시뮬레이션과 실물에 쓴다 | [software.md](../software.md) |
| 서포트 없는 형상으로 설계하고, 출력 방향은 코드에서 정한다 | AMS가 고장이라 서포트가 같은 재료로 나온다. FDM은 층 사이가 약하다 | [manufacturing.md](../manufacturing.md) |
| 구조는 PLA, 탄성 부품은 PETG, 패드는 TPU. ABS·ASA와 카본·유리섬유 필라멘트는 쓰지 않는다 | PLA가 단단해 처짐에 유리하다. 출력 중 유해 가스와 노즐 마모를 피한다 | [manufacturing.md](../manufacturing.md) |
| 팔은 두 가지 색 (어두운 구조색, 밝은 덮개색) | 필라멘트 비용을 줄이고 협동로봇 외형을 낸다 | [manufacturing.md](../manufacturing.md) |

## 영향

- 위 결정의 현재 내용은 각 주제 문서에 있다.
- 체결 방식은 [0003](0003-fastening-nut-traps.md)에서 너트 홈으로 바뀌었다.
- 모터 배치는 [0011](0011-joint-drives.md)에서 어깨 ST-3120, 팔꿈치 STS3250으로 바뀌었다.
- 손목 형식과 D405 자리는 [0013](0013-wrist-type.md)에서 UR형, J6 앞 손목 하우징으로 바뀌었다.
