# 0002. 문서 체계

- 상태: 채택
- 날짜: 2026-11-06

## 배경

레포는 GitHub에 공개하고, 여러 PC와 여러 Claude Code 세션에서 이어서 작업한다. Claude의 자동 메모리는 PC마다 따로 저장되므로, 작업을 이어가는 데 필요한 정보는 전부 레포 문서에 있어야 한다. 모든 결정은 근거와 함께 남긴다. 문서를 읽는 사람은 레포 주인 한 명이다.

참고한 Claude Code 공식 문서 내용 (2026-11 확인):

- CLAUDE.md는 세션이 시작될 때 자동으로 읽힌다. 짧고 구체적일수록 잘 지켜지고, 다른 문서 내용은 복사하지 말고 링크하라고 권한다.
- CLAUDE.local.md(git에서 빠지는 개인용)와 .claude/rules/(paths로 지정한 파일을 다룰 때만 읽히는 규칙)가 있다.
- 자동 메모리는 PC마다 따로다.

## 검토한 대안과 결정

여러 갈래를 한 번에 정해서 표로 묶었다.

| 정할 것 | 결정 | 검토한 대안 | 근거 |
|---|---|---|---|
| 문서 나누기 | README와 CLAUDE.md는 짧게, 내용은 docs/에 주제별로 | 큰 문서 하나 / CLAUDE.md에 전부 | 큰 문서는 커질수록 찾기 어렵고 세션마다 통째로 읽어야 한다. CLAUDE.md는 매 세션 전부 읽히므로 짧아야 한다 |
| docs 구조 | 주제마다 파일 하나, 커지면 그 주제만 폴더로 | 처음부터 주제별 폴더 / Diátaxis 같은 분류 틀 | 내용 없는 폴더와 깊은 탐색을 피한다. Diátaxis는 제품 사용 설명서용 틀이라 설계 기록과 맞지 않는다. 나중에 나누는 비용은 링크 몇 개다 |
| 결정 기록 위치 | 결정마다 파일 하나 (ADR) | 주제 문서 안에 이유까지 / 결정 로그 파일 하나 | 주제 문서 안에 쓰면 결정이 바뀔 때 옛 이유가 지워지거나 문서가 비대해진다. 로그 하나는 길어지면 찾기와 링크가 어렵다 |
| 결정 기록 양식 | 배경 → 대안 → 결정 → 근거 → 영향 | ADR 원형(대안 칸 없음) / 자유 형식 | 대안 칸이 있어야 트레이드오프가 남는다. 자유 형식은 빠지는 항목이 생긴다 |
| 진행 상황 | status.md 하나에 지금 상태만 | 날짜별 작업 일지 / GitHub 이슈 | 일지는 쌓일수록 지금 상태를 찾기 어렵다. 이슈는 레포 밖이라 별도 도구와 인터넷이 있어야 읽고, 공개된다. 지난 이력은 git 기록과 결정 기록으로 충분하다 |
| 언어 | 본문, 주석, 커밋 메시지는 한국어. 코드와 파일 이름은 영어 | 영어 | 읽는 사람이 레포 주인 한 명이다 |
| 비공개 자료 | docs-local/을 .gitignore로 제외하고, 다른 PC로는 손으로 옮긴다 | .git/info/exclude / 비공개 레포 | exclude는 PC마다 설정해야 해서 다른 PC에서 실수로 커밋될 수 있다. 비공개 레포는 관리할 것이 는다. 대신 작업에 꼭 필요한 정보는 docs-local/에 두지 않는다 |
| 부품표 | 데이터 파일이 원본이고, bom.md는 스크립트가 만든다 | md 표만 / 엑셀·구글 시트 | 합계와 예산이 자동으로 맞고 값 검사가 된다. 나중에 자동 생성되는 설계 부품표와 바로 비교할 수 있다. 엑셀은 git에서 변경이 안 보이고 Claude가 고치기 어렵다. 구글 시트는 레포 밖이라 Claude가 읽을 수 없다 |
| Claude 부가 기능 | CLAUDE.local.md, .claude/rules/, 전용 스킬은 지금 쓰지 않는다 | 처음부터 쓰기 | 쓸 곳이 생기기 전에 만들면 관리할 것만 는다. 필요해지면 결정 기록을 쓰고 추가한다 |

## 영향

- 문서 위치와 쓰는 법은 [conventions.md](../conventions.md)에 있다.
- 부품표 데이터 형식은 치수 값 파일 형식과 같이 아키텍처 결정에서 정한다. 스크립트가 생기기 전까지 살 것은 [status.md](../status.md)에 적는다.
- 다른 프로젝트가 들어오면 팔 전용 문서를 docs/<프로젝트 이름>/ 아래로 옮긴다.
