# 0023. 로봇 컨트롤러와 응용의 경계

- 상태: 채택
- 날짜: 2026-11-11 (제안 2026-11-10)

## 배경

- 첫 대표 작업은 미니 랜덤 팔레타이징이지만 팔레타이징만 하는 로봇이 아니다. 물건 집기, 용접 흉내처럼 여러 작업에 쓴다 ([goals.md](../goals.md)의 6축 확인 작업과 도구 교체도 같은 방향이다).
- [0009](0009-control-architecture.md)는 경로 계획이 시간이 붙은 관절 궤적을 실행 루프에 보내는 데까지 정했다. 여러 작업에서 실물 로봇을 어떻게 제어할지, 어디까지가 로봇이고 어디부터가 작업인지는 정하지 않았다.
- 컨트롤러는 로봇 옆 컨트롤러 파이에서 Rust로 돌고, PC 없이도 쓴다 ([0025](0025-controller-on-pi.md)). 파이는 로봇을 쓸 때만 켠다 ([0026](0026-pi-runtime-deploy-records.md)).
- 산업용 컨트롤러, 데스크톱·오픈소스 팔, 전송 방식을 조사했다 ([controller-research.md](../controller-research.md) 1~3절).
- 사용 조건 (사용자, 2026-11-11): 펜던트로 쓰는 폰은 안드로이드다. 집 랜 안에서 혼자 쓰고, 밖에서 집으로 들어오는 길은 만들지 않는다.

### 하드웨어가 정하는 한계

서보가 위치 제어 서보라서 산업용 컨트롤러의 기능이 다 되지는 않는다.

| 기능 | 이 로봇 |
|---|---|
| 관절 이동, 직선 이동, 조그, 속도 조절, 한계, 정지, 상태 내보내기, 시뮬레이터 | 된다 |
| 블렌드 | 된다. 다만 직교 경로의 모서리 잇기, 시간 매기기, IK 잇기가 가장 공이 드는 부분이다. 산업용처럼 일정한 속도까지는 어렵고, 보기에 매끄러운 수준을 노린다 |
| 부딪히면 멈추기 | 어림만 된다. 서보가 읽는 부하로 큰 충돌 정도만 잡는다 |
| 손으로 끌어서 티칭 | 어렵다. 토크를 끄면 팔이 떨어진다 |
| 힘 제어, 안전 인증 수준의 정지 | 안 된다 |
| 실시간 보장 | 컨트롤러 파이는 리눅스라 실시간 우선순위와 실시간 커널을 쓸 수 있다 ([0026](0026-pi-runtime-deploy-records.md)). 개발할 때 PC(Windows)에서 돌리면 보장이 없다 |

## 검토한 대안

자료는 [controller-research.md](../controller-research.md)에 있다.

| 정할 것 | 대안 | 판단 |
|---|---|---|
| 경계 | 응용이 관절 궤적을 직접 보낸다 (0009 그대로) / 컨트롤러가 이동 명령을 받는다 (산업용) | 컨트롤러가 이동 명령을 받는다 |
| 전송 | 컨트롤러가 HTTPS와 WSS를 직접 연다 / Zenoh / ZeroMQ / gRPC / MQTT | 컨트롤러가 직접 연다. 나머지는 브라우저 앞에 중계기나 브리지가 필요하다 |
| 데드맨 | 전송 방식의 연결 확인 / 누르는 동안 보내는 메시지를 컨트롤러가 잰다 | 메시지를 잰다 |
| 폰 화면의 HTTPS | 사설 인증 기관 / 가진 도메인 + Let's Encrypt (DNS-01) | 도메인 |
| 정지 | 전원 차단 (산업용 Cat 0·1) / 감속해 토크를 켠 채 버팀 (Cat 2) | 버팀 |
| 게임패드 자리 | 컨트롤러 파이 / PC / 폰 브라우저 | 컨트롤러 파이 |

## 결정

산업용 로봇처럼 로봇 컨트롤러와 응용을 나눈다.

```
[응용]  팔레타이징 | 물건 집기 | 용접 흉내 | …          PC
   작업 순서, 비전, 작업 공간 지식 (팔레트 위치 등)
        │ 이동 명령 ↓   ↑ 상태, 이벤트          WSS, 집 랜 (4)
═══════════════ 컨트롤러 API ═══════════════
[로봇 컨트롤러]  컨트롤러 파이. 어떤 응용에도 종속되지 않는다
   명령 줄 → 경로 계획 (IK, 보간, 블렌드, 시간 매기기) → 관절 궤적
     → 실행 루프 + 안전 검사 (0009) → 실물 서보 | 시뮬레이션
   도구 (끝점, 그리퍼), 보정, 상태 내보내기, 기록 (0026)
[펜던트]  게임패드(파이에 꽂음), 폰 브라우저 → 컨트롤러에 붙는 손님
```

- 컨트롤러는 파이가 켜져 있는 동안 도는 서비스이고 API를 준다: 이동 명령, 정지, 관리 명령(토크 켜기·끄기, 실물·시뮬레이션 전환), 상태 흐름, 이벤트. UR의 URScript, RTDE, Dashboard Server에 해당한다.
- 경계는 둘이다: 응용 ↔ 컨트롤러(이동 명령)와, 컨트롤러 안의 경로 계획 ↔ 실행 루프(관절 궤적, 0009).
- 컨트롤러를 시뮬레이션으로 띄우면 응용은 실물과 같은 API로 붙는다 (UR의 URSim처럼). 실물이 없는 PC에서 응용을 만든다 ([0022](0022-records-and-sync.md)).

### 1. 경계

- 컨트롤러: IK, 이동 명령과 블렌드, 시간 매기기, 한계, 안전 검사, 정지와 복구, 조종권과 모드, 조그, 웨이포인트·프로그램 저장과 재생. 공구 끝점(TCP), 짐 무게, 이름 붙은 좌표계를 저장하고, 로봇 모델(URDF·MJCF)을 내준다.
- 그리퍼: 언제 잡고 놓을지는 응용이 정한다. 구동, 폭과 서보 값 사이 변환, 전류로 하는 힘 제한, 잡았는지 판정(목표 폭 전에 멈추고 부하가 오름), 정지 중에도 쥔 채 버티기, 달린 그리퍼 알아보기(서보 ID, [design.md](../design.md#그리퍼-교체-구조))는 컨트롤러가 한다.
- 응용: 작업 순서, 비전, 팔레트 배치, 좌표계를 재서 구하는 일. 응용은 API가 자리 잡을 때까지 같은 레포에 둔다.
- 장애물을 피하는 경로 계획은 응용에 둔다. 컨트롤러는 한계와 자기 충돌만 본다.
- 손목 D405의 핸드아이 값은 로봇과 카메라 받침에 매인 값이라 로봇 설정(`data/`)에 두고 컨트롤러가 내준다. 카메라는 컨트롤러가 아니라 카메라 파이의 서비스다.
- 로봇보다 컨트롤러가 먼저 커지지 않게 한다. 경계와 큰 구조는 지금 정하고, 기능은 실제 응용이 필요할 때 더한다. API가 바뀌어도 응용은 클라이언트 라이브러리 한 곳만 고친다.

### 2. API

- 처음에는 실제 응용이 쓰는 것만 둔다.
- 명령은 바로 결과를 돌려준다: 성공, 조종권 없음, 상태가 맞지 않음, 값이 틀림, 그 밖 (UR 제어 API의 0, -1, -2, -100과 같은 나눔).
- 명령 묶음:

  | 묶음 | 명령 |
  |---|---|
  | 조종권 | 받기, 돌려주기 |
  | 토크 | 켜기(그 자리에서 버팀), 끄기 |
  | 복구 | 보호 정지 풀기(이유 확인), 고장 지우기 |
  | 이동 | 관절 이동, 직선 이동(원호는 나중). id를 붙여 줄 세우고 줄 길이에 제한을 둔다 |
  | 그리퍼 | 열기, 잡기(폭, 힘, 속도). 이동과 같은 줄에 세우거나 바로 실행한다 |
  | 흐름 | 멈춤, 이어서, 정지, 줄 비우기 |
  | 속도 | 속도 비율 |
  | 조그 | 흐름(수명이 지나면 멈춤), 한 스텝 |
  | 티칭 | 웨이포인트·프로그램 저장, 불러오기, 재생 |

- 그리퍼 명령을 이동과 같은 줄에 세우면 "내려가기 → 잡기 → 올라가기"의 순서를 컨트롤러가 지키고, 못 잡으면 줄을 멈추고 알린다. 펜던트에서는 바로 실행한다.
- 블렌드 규칙: 블렌드가 겹치면 반지름을 줄이고 건너뛰지 않는다 (UR 모션 버전 2). 블렌드 구역에 들어설 때 다음 이동이 없으면 그 점에서 정확히 멈추고 경고를 낸다 (ABB).
- 상태 흐름: 실행 루프 주기로 내고, 클라이언트마다 솎는 비율을 고른다 (UR RTDE). 폰 화면은 20~30 Hz면 된다. 항목은 시각, 순번, 로봇 상태(끊김, 토크 꺼짐, 대기, 동작), 안전 상태(정상, 보호 정지, 고장), 프로그램 상태와 지금 이동 id, 줄 길이, 조종권 주인과 모드, 속도 비율(설정 값과 실제 값), 목표·실제 관절 각, 공구 끝점 자세, 그리퍼 폭과 잡음 여부, 서보마다 온도·부하·전압·오류 비트, 백엔드(실물, 시뮬레이션), 프로토콜 판이다.
- 이벤트는 순번을 붙여 바로 민다: 이동 끝남·실패·취소, 그리퍼 잡음·못 잡음, 블렌드 조정, 보호 정지(이유, 관절, 코드), 조종권·모드 바뀜, 흐름 시간 넘김.
- 움직임 종류는 둘로 시작한다: 줄 세운 이동(블렌드)과 최신 목표만 따르는 흐름(조그). 지금 상태에서 다시 계획하는 이동과 서보 흐름(시각 서보)은 필요할 때 더한다.

### 3. 조종권과 모드

- 한 번에 하나만 조종하고, 상태 보기는 누구나 한다. 조종권은 연결에 묶는다.
- 펜던트(파이에 꽂은 게임패드, 폰 화면)는 로봇 옆으로 보고 언제든 조종권을 가져간다. 응용은 명시적으로 받고 돌려준다.
- 받는 방법: 응용은 클라이언트 라이브러리의 받기·돌려주기를 부른다. 보통 프로그램이 시작할 때 받고 끝날 때 돌려줘서, 사람이 누를 것은 없다. 펜던트는 움직이는 입력(조그, 실행, 게임패드 데드맨)을 누르는 순간 가져가고, 따로 받는 버튼은 없다. 화면은 지금 조종권을 쥔 쪽을 늘 보여 준다.
- 정지는 조종권 없이 누구나 한다.
- 오류나 보호 정지가 나면 조종권이 컨트롤러로 돌아가고 다시 받아야 한다 (FANUC). 조종하던 연결이 끊기거나 데드맨이 걸리면 조종권이 풀리고 감속해 버틴다.
- 컨트롤러가 모든 명령 길에서 조종권을 지킨다. Reachy Mini처럼 우회되는 잠금은 두지 않는다.
- 수동 모드(펜던트)는 누르는 동안만 움직이고 속도 상한을 둔다. 상한은 산업용의 250 mm/s보다 낮게, 관절 시험과 팔 시험으로 정한다. 자동 모드는 응용과 프로그램 재생이다.
- 모드는 펜던트 화면에서 길게 눌러 바꾼다. 켤 때와 보호 정지 뒤에는 늘 수동 모드로 시작한다.
- 조종권을 받을 때 PIN 같은 인증은 두지 않는다.

### 4. 펜던트와 전송

- 펜던트는 둘이다.
  - 게임패드: 조그. 트리거를 데드맨으로 쓴다.
  - 폰(안드로이드): 브라우저로 컨트롤러의 웹 화면에 들어간다 (앱을 설치하지 않는다). 상태, 저장한 자세, 프로그램 실행·정지, 카메라 화면, 화면 조그. PC 브라우저도 같은 화면을 쓴다. 계획해 둔 3D 화면([software.md](../software.md#패키지)의 React(R3F))과 합친다.
- 펜던트에는 실제 비상정지 버튼과 데드맨 스위치가 없으므로 이렇게 막는다.
  - 누르고 있을 때만 움직이고, 손을 떼거나 터치가 취소되면(전화, 알림 등) 멈춘다.
  - 명령이 끊기면(와이파이, 화면 꺼짐, 탭 전환) 컨트롤러가 멈춘다. 조그를 짧은 궤적으로 보내는 0009의 방식이 이를 받쳐 준다.
  - 화면의 정지는 소프트웨어 정지다. 최종 수단은 가변 전원 차단이다 ([hardware.md](../hardware.md#안전)).
- 컨트롤러의 Rust 프로세스 하나가 펜던트 화면(HTTPS)과 WSS API 하나를 연다. 브라우저, Python 응용, 게임패드가 모두 여기에 붙는다. 집 랜 안에서만 연다.
- 메시지는 JSON(`{type, id, seq, t, body}`)으로 시작한다. 명령은 id로 답하고, 이벤트와 상태는 밀어 준다. 클라이언트마다 받을 주제와 주기를 고르고, 최신 상태 한 칸만 두어 와이파이가 밀려도 묵은 상태가 쌓이지 않게 한다.
- 데드맨은 누르는 동안 정해진 간격으로 보내는 메시지를 컨트롤러가 직접 잰다. 끊겼다고 볼 시간은 폰에서 파이까지 와이파이 왕복 시간을 잰 뒤 정한다.
- 들고 나는 메시지는 컨트롤러가 MCAP로 기록한다. 늘 켜 두는 기록은 메모리 링 버퍼에만 두고 보호 정지·오류 때 파일로 남기며, 시험 기록은 세션 파일로 파이가 드라이브에 올린다 ([0026](0026-pi-runtime-deploy-records.md)).
- Python 클라이언트 라이브러리는 실물 컨트롤러와 PC 시뮬레이션 컨트롤러에 같게 붙는다.
- 폰 화면의 HTTPS 인증서는 가진 Route 53 도메인으로 Let's Encrypt에서 DNS-01로 받는다. NAS의 DSM 내장 Let's Encrypt는 사용자 도메인에 HTTP-01만 지원해 이중 NAT인 집에서는 안 되므로 따로 받는다 ([controller-research.md](../controller-research.md#6-nas-쓸-자리)). 집 공유기가 공개 DNS의 사설 주소 답을 막는지(DNS 재바인딩 보호)는 만들기 전에 확인한다.
- 컨트롤러 메시지에는 pyzmq를 쓰지 않는다. 카메라 파이에서 PC로 가는 영상에는 그대로 둔다 ([0008](0008-environment-and-packages.md)). 여러 기계가 서로 얽히면 컨트롤러 안쪽에 Zenoh를 더하고, 브라우저 출입구는 그대로 둔다 (리서치의 설계 B).

### 5. 컨트롤러 자리

[0025](0025-controller-on-pi.md)에서 정했다: 로봇 옆 컨트롤러 파이이고, PC 없이도 쓴다.

### 6. 로봇 옆에 없는 PC

- 밖에서 집으로 들어오는 길이 없어서, 집 밖의 PC는 실물에 닿지 않는다. 시뮬레이션과 기록 분석(드라이브로 받은 기록)만 한다.
- 집 안 PC의 응용은 3의 규칙대로 조종권을 받아 움직인다.
- 나중에 밖에서 들어오는 길을 열면, 원격 응용이 조종권을 받을 때 로봇 옆 펜던트에서 정해진 시간 안에 허락하게 하고(ABB의 RMMP) 인증을 더한다.

### 7. 브레이크가 없는 팔의 정지

- 보호 정지와 소프트웨어 정지는 감속해 토크를 켠 채 버틴다 (산업용 Cat 2, 0009와 같다). 그리퍼(흡착 포함)도 쥔 채 둔다.
- 토크를 끄거나 쥔 것을 놓는 것은 사람이 명시적으로 할 때와 서보 자체 보호가 끊을 때뿐이다.
- 최종 수단은 그대로 가변 전원 차단이다 ([hardware.md](../hardware.md#안전)).

### 8. 게임패드

- 컨트롤러 파이에 꽂고 컨트롤러 프로세스가 직접 읽는다.
- 크레이트는 순수 Rust인 evdev를 먼저 본다. gilrs는 리눅스에서 C 라이브러리(libudev)가 필요해 정적 빌드([0026](0026-pi-runtime-deploy-records.md))와 부딪힌다.

## 근거

- 경계: 산업용(UR, ABB)과, 로봇 옆에 컨트롤러를 둔 데스크톱 팔(xArm, Reachy, PAROL6 서버)이 모두 이렇게 나눈다. 블렌드는 다음 명령을 미리 알고 관절 한계와 IK를 아는 쪽이 해야 한다 (UR의 블렌드 반지름, ABB의 zone). 응용마다 IK와 블렌드를 다시 짜지 않고, 펜던트도 응용 없이 같은 길로 움직인다. 0009를 뒤집지 않고 그 위에 한 층을 더한다.
- 그리퍼: 그리퍼 서보가 관절과 같은 버스에 있어서 버스를 쥔 컨트롤러만 다룰 수 있다. 응용이 끊겨도 쥔 것을 놓지 않아야 하고, 힘 제한은 누가 명령하든 걸려야 하며, PC 없이 펜던트로 티칭할 때도 열고 닫아야 한다.
- 조종권: 펜던트와 응용이 함께 명령하면 로봇이 엇갈린 명령을 받는다. 오류 뒤에 다시 받게 하면, 멈춘 까닭을 모르는 응용이 그대로 이어 움직이지 않는다. 연결이 끊긴 쪽의 명령은 끝까지 따르지 않고 멈춘다. 정지는 누가 조종권을 쥐고 있든 막히면 안 된다.
- 전송: 브라우저가 중계 없이 붙는 것은 컨트롤러가 직접 여는 WebSocket이고, 파이에 더 띄울 것이 없다. 부하는 어느 방식이든 넉넉하다. 화면 켜 두기(Wake Lock)와 Gamepad API는 HTTPS에서만 된다.
- 데드맨: 전송 방식의 연결 확인은 가장 짧아도 초 단위다 (Zenoh 10 s, websockets ping 20 s). 브라우저의 JavaScript는 WebSocket ping을 보낼 수 없다.
- HTTPS: 사설 인증 기관은 기기마다 뿌리 인증서를 깔아야 하고, 안드로이드 Chrome이 사용자가 넣은 인증서를 믿는지는 확인하지 못했다. 도메인은 이미 있어서 더 드는 돈이 없다.
- 정지: 산업용 Cat 0·1은 브레이크가 팔을 잡는다는 전제다. 이 팔은 브레이크가 없어 전원을 끊으면 팔과 쥔 것이 떨어진다.
- 게임패드: 파이에 꽂으면 데드맨이 와이파이를 건너지 않고, PC 없이도 된다.
- 인증과 원격 허락: 집 랜 안에서 혼자 쓰고 밖에서 들어오는 길이 없어서 지금은 막을 대상이 없다.

## 영향

- [0009](0009-control-architecture.md)를 고쳤다: 경로 계획 위에 이 경계를 두고, 전송은 4의 WSS다. 경로 계획이나 조종하던 연결이 끊기면 궤적을 끝까지 가지 않고 감속해 버틴다 (3).
- 메시지 형식과 궤적 형식은 만들 때 이 경계로 정한다. 팔 움직이기 단계([0025](0025-controller-on-pi.md))에서 경로 계획이 PC에 있는 동안은 PC가 관절 궤적을 같은 WSS로 보낸다.
- [0020](0020-suction-gripper.md): 흡착도 정지 때 쥔 채 둔다.
- 서보 버스(컨트롤러의 맨 아래층)는 이 경계와 상관없이 먼저 만든다 ([0024](0024-servo-bus.md)).
- 만들 때 정한다:
  - 블렌드와 경로 시간 매기기 도구 (후보와 라이선스는 리서치에 있다)
  - 직교 경로를 따라 IK를 끊김 없이 잇는 방법, 특이점 처리
  - 브라우저 펜던트 세부 (터치 처리, 화면 켜 두기)
  - 데드맨 간격과 끊김 시간 (와이파이 왕복 시간을 잰 뒤)
  - 수동 모드 속도 상한 (관절 시험과 팔 시험 뒤)
- 다시 볼 조건: 밖에서 들어오는 길을 열 때 (6), 응용 여럿이 동시에 돌거나 카메라를 여러 응용이 같이 쓸 때 (4의 Zenoh).
