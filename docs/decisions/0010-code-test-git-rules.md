# 0010. 코드, 테스트, git 규칙

- 상태: 채택
- 날짜: 2026-11-07

## 배경

- 코드는 주로 Claude가 쓰고, 여러 PC와 세션에서 이어서 쓴다. 그래서 규칙이 문서와 도구 설정에 있어야 한다.
- 값 파일은 mm와 도, 코드 안은 SI로 정했다 ([0006](0006-data-and-pipeline.md)). build123d의 기본 단위는 mm이고(`MM = 1`), 출력 파일(STL, 3MF)도 mm로 읽힌다.
- MJCF, URDF, FK가 어긋나는 흔한 원인은 단위와 변환 표기의 혼동이다 ([software.md](../software.md#구현할-때-알아-둘-것)).
- 이전 프로젝트에서는 테스트나 시뮬레이션이 실물 모터를 움직일 수 있어서 격리가 필요했다 ([background.md](../background.md#이전-프로젝트의-연결-구조)).
- 편집기는 VS Code다 (OCP CAD Viewer). VS Code의 Python 검사(Pylance)는 pyright 엔진을 쓴다.

## 검토한 대안과 결정

여러 갈래를 한 번에 정해서 표로 묶었다. 대안을 따질 것 없는 관례는 아래 "그 밖의 규칙"에 있다.

| 정할 것 | 결정 | 검토한 대안 | 근거 |
|---|---|---|---|
| 단위 | 코드는 SI(m, rad, s, kg, N·m). build123d로 부품을 그리는 코드만 mm. SI가 아닌 값을 함수 인자, 반환 값, 필드로 주고받을 때는 이름에 단위를 붙인다 (`_mm`, `_deg`, `_g`). 단위는 값 파일을 읽을 때, 로봇 기술에서 부품 코드로 넘길 때, 화면·파일로 내보낼 때만 바꾼다 | 단위 라이브러리(pint) / 코드 전체를 mm | pint는 numpy, MuJoCo, build123d를 지날 때마다 단위를 떼고 붙여야 해서 번거롭고 느리다. 전체를 mm로 하면 MuJoCo, IK, 토크 계산 곳곳에 변환이 생긴다. 바꾸는 곳을 셋으로 묶고, 남는 실수는 FK 대조 테스트와 치수 테스트로 잡는다 |
| 자세 표현 | 4×4 동차 변환 행렬(numpy)로 주고받는다. 이름은 `T_a_b`이고, b 좌표계를 a 좌표계에서 본 자세다 (b의 좌표를 a의 좌표로 바꾼다). 그래서 `T_a_c = T_a_b @ T_b_c`처럼 가운데 글자가 맞물린다. 쿼터니언과 오일러 각은 MuJoCo, URDF, 사람이 보는 값 같은 경계에서만 쓴다 | 쿼터니언 + 위치 / 라이브러리 객체 (mink의 SE3 등) | 쿼터니언은 라이브러리마다 순서가 달라(MuJoCo는 w가 앞, SciPy는 뒤) 실수가 잦다. 라이브러리 객체는 그 라이브러리에 묶인다. 행렬은 EAIK, MuJoCo, numpy가 바로 쓰고, 이름만 봐도 곱하는 순서가 맞는지 보인다 |
| 링크 좌표계 | 영점 자세에서 모든 링크 좌표계의 방향을 베이스 좌표계와 같게 둔다. 관절 원점은 부모 링크 좌표계에서 위치만 주고(회전 없음), 관절 축은 단위 벡터로 준다. 회전이 필요한 좌표계는 플랜지와 TCP 같은 고정 좌표계뿐이다 | 관절마다 축이 z가 되게 좌표계를 돌린다 (DH 방식) | 축이 직교하거나 평행하게 설계하므로 회전 없이 표현된다. URDF의 rpy와 MJCF의 회전이 모두 0이라 변환 실수가 없고, 해석적 IK(EAIK)에 넣을 축과 위치가 그대로 나온다 |
| 관절과 링크 이름 | 관절 `j1`~`j6`, 바디 `base`, `link1`~`link6`, 사이트 `flange`, `tcp`. MJCF, URDF, 로봇 설정, 메시지에서 같은 이름을 쓴다. 그리퍼는 붙일 때 그리퍼 이름을 접두어로 붙인다 | 기능 이름 (`shoulder_pitch`, `wrist_roll`) | 기능 이름은 손목 형식(구형, UR형)에 따라 바뀐다. 번호 이름은 문서의 J1~J6과 같다 |
| 포맷, 린트 | ruff (포맷, 린트, import 정렬) | black + flake8 + isort | 도구 하나로 빠르다 |
| 타입 검사 | pyright, standard 모드. servo 패키지는 strict 모드 | mypy / ty | 편집기(Pylance)와 같은 엔진이라 화면과 명령의 결과가 같다. mypy는 Pylance와 판정이 다를 수 있다. ty는 이 시점의 완성도를 확인하지 않았다. 실물을 움직이는 motor는 더 엄격하게 본다 |
| 테스트 위치 | pytest. 패키지마다 `packages/<이름>/tests/`. 패키지를 넘나드는 검사(의존 방향, 로봇 설정과 설계의 일치)만 루트 `tests/`. import 방식은 importlib | 루트 `tests/` 하나 | 패키지별로 두면 경계가 맞고, motor 테스트만 파이에서 돌릴 수 있다. importlib 방식은 패키지마다 같은 테스트 파일 이름이 있어도 충돌하지 않는다 (pytest가 새 프로젝트에 권하는 방식) |
| 테스트 분류 | 표시 없음(빠른 것), `slow`(CAD 생성처럼 느린 것), `hardware`(실물 서보·카메라). 기본 실행은 `hardware`를 뺀 전부다. `hardware`는 옵션을 줘야 돌고(한 프로세스로만), Claude는 확인을 받은 뒤에만 돌린다. 기본 실행은 여러 프로세스로 나눠 돈다 (pytest-xdist, 하나로 돌리면 9분이 넘었다). 실물 백엔드는 `hardware` 테스트에서만 만든다 | 표시 없이 전부 | 테스트가 실물을 움직이면 안 된다 |
| 의존 방향 검사 | 패키지마다 허용한 패키지만 import하는지 소스를 읽어 확인하는 테스트 하나 | import-linter | 규칙이 짧아서, 의존성을 하나 늘리는 것보다 직접 쓰는 게 낫다 |
| 커밋 전 검사 | 커밋 전에 포맷, 린트, 타입, 테스트(`hardware` 제외)를 돌린다. 명령은 CLAUDE.md에 둔다 | pre-commit 프레임워크 / git 훅 | 커밋은 대부분 Claude가 한다. 훅은 PC마다 설치해야 하고 도구가 는다. 검사를 빠뜨리는 일이 생기면 훅을 더한다 |
| CI | 지금은 두지 않는다 | GitHub Actions | 혼자 쓰고, 커밋 전 검사를 돌린다. 의존성이 무거워 CI가 느리다. PC마다 결과가 달라지는 일이 생기면 더한다 |
| 줄바꿈 | `.gitattributes`에 `* text=auto eol=lf`. 작업 폴더도 LF | Git for Windows 기본 (작업 폴더는 CRLF) | PC마다 git 설정이 달라도 결과가 같다. 편집기와 Python은 LF를 문제없이 다룬다 |
| 라이선스 | MIT. 저작권자 표기는 GitHub 계정 이름(zzingobomi) | Apache-2.0 / 라이선스 없음 / 하드웨어용 라이선스 (CERN-OHL) | 가장 짧고 널리 쓰여서 조건을 누구나 바로 안다. Apache-2.0의 특허 조항은 기여자가 많을 때 의미가 있어서 혼자 하는 레포에서는 형식만 는다. 라이선스가 없으면 공개해도 남이 가져다 쓸 수 없다. 출력 파일은 코드가 만들므로 하드웨어용 라이선스를 따로 둘 필요가 없다 |

## 그 밖의 규칙

관례를 따르는 것들이다.

- 좌표계는 오른손 좌표계다. 베이스 좌표계는 설치면 중심에서 z가 위, x가 작업대 쪽이다. 플랜지 좌표계는 z가 플랜지 면에서 도구 쪽이다 (ISO 9787의 관례). 관절의 양의 방향은 관절 축에 대한 오른손 법칙이다. 영점 자세와 축 방향은 골격 설계에서 정한다.
- 코드는 PEP 8을 따르고 이름은 영어로 쓴다. 공개 함수에는 타입 힌트를 단다.
- 주석과 docstring은 한국어로 쓰고, 코드만 봐서는 모를 "왜"를 쓴다.
- 파일은 UTF-8로 열고, 경로는 `pathlib`으로 다룬다 ([0008](0008-environment-and-packages.md)).
- 출력은 `print` 대신 `logging`을 쓴다. 명령줄 도구가 결과를 보여 주는 출력은 예외다.
- 결정 기록에 쓰는 계산 결과는 검토 코드로 다시 만들 수 있게 하고, 기록에 실행 명령을 적는다. 숫자가 손으로 옮겨 적은 채 코드와 어긋나지 않게 하려는 것이다.
- 브랜치는 main 하나에 커밋하고, 위험한 실험만 짧은 브랜치에서 한다.
- 커밋 메시지는 한국어로 쓴다. 첫 줄에 바뀐 것을 요약하고, 자세한 건 빈 줄 다음에 쓴다. Claude가 쓴 커밋에는 `Co-Authored-By` 줄을 단다.
