# 서보 준비

제작 로드맵 2단계(서보와 연결 준비)의 순서와 명령이다. 첫 연결(찾기, 덤프, 통신 시간, ID 바꾸기)은 Python 기준 구현으로, 값 적용과 맨 서보 확인은 컨트롤러로 한다 ([0024](decisions/0024-servo-bus.md) 만드는 순서 3번, 5번).

## 첫 연결

서보를 하나씩 어댑터에 이어 ID를 관절 번호로 바꾼 뒤, 7개를 모두 이어 설정을 남기고(덤프) 통신 시간을 잰다 ([0024](decisions/0024-servo-bus.md)). 명령은 Python 기준 구현(`packages/servo`)에 있다.

- 서보를 움직이지 않는다. 목표 위치도 쓰지 않는다. 각도 한계 밖에 놓인 서보에 목표를 쓰면 한계까지 움직일 수 있어서다.
- `scan`과 `dump`는 읽기만 한다. `timing`은 두 가지를 쓴다. 동기 쓰기 자리에 토크 제한(RAM)으로 읽은 값을 그대로 쓰고, 응답 지연(7번)은 잠근 채 0으로 바꿔 한 번 더 잰다. 서보 전원을 껐다 켜면 둘 다 처음 값으로 돌아간다. `set-id`는 ID를 EEPROM에 써서 전원을 꺼도 남는다. 버스에 서보가 하나만 있을 때만 바꾸고, 바꾸기 전후의 덤프를 기록한다. 그래서 `timing`과 `set-id`는 `--yes`를 붙여야 돌고, Claude는 돌리기 전에 확인을 받는다.
- 기록은 `records/servo/<날짜시각>_<명령>-<컴퓨터>/`에 남는다: `meta.json`(조건, 코드 커밋, 서보마다의 덤프나 통신 시간 요약)과, `timing`은 `samples.csv`(잰 것 하나하나)도 남긴다.
- 명령은 Claude가 돌리고 출력을 읽는다. 기록은 명령이 파일로 남겨서 숫자를 옮겨 적지 않는다. 사용자는 손으로 하는 일을 하고, 프로그램이 볼 수 없는 것을 알려 준다: 꽂은 서보 수, 가변 전원 화면의 전압과 전류, C.C 표시등, 서보 LED가 깜박이는지, 타는 냄새 같은 이상.

### 준비

- 서보: 가진 STS3215 여섯과 STS3250 하나. 20 cm 서보 케이블이 6개뿐이면 서보 6개로 잰다. 버스 시간은 서보 수에 비례하므로 7개는 셈으로 늘리고, 케이블이 더 오면 다시 잰다.
- 서보 어댑터 (점퍼 B, [hardware.md](hardware.md#서보-어댑터))와 USB-C 케이블. 데이터가 되는 케이블이면 길이는 상관없다. 충전만 되는 케이블이면 `ports`에 어댑터가 보이지 않는다.
- 가변 전원과 전용 전원선. 가변 전원 쪽은 바나나 플러그, 어댑터 쪽은 나사 단자다 ([hardware.md](hardware.md#전원)).
- 바나나 플러그가 오기 전에는 첫 연결과 맨 서보 확인(짐 없는 서보 하나, 짧게)을 가변 전원의 리드선(가변 전원 쪽 바나나 플러그, 반대쪽 악어 클립)으로 해도 된다 ([0016](decisions/0016-servo-power.md)의 연결).
  - 어댑터 나사 단자에 빨강·검정 선을 물리고(빨강 DC+, 검정 DC−), 그 선의 벗긴 끝에 같은 색 클립을 문다. 클립은 피복이 아니라 구리를 물게 하고, 살짝 당겨 빠지지 않는지 본다.
  - 클립은 어댑터에서 한 뼘 이상 떨어지게 둔다. 빠진 클립이 어댑터에 닿으면 12 V가 USB 쪽으로 들어가 어댑터나 PC의 USB 포트가 망가질 수 있다. 두 클립은 서로 닿지 않게 떼어 각각 테이프로 책상에 붙인다.
  - 클립은 + 플러그를 뺐을 때만 물리고 뗀다. 켜고 끄는 것은 빨강 리드선의 바나나 플러그를 가변 전원의 + 단자에서 빼고 꽂아서 한다 (아래 순서 그대로).
  - 짐을 걸거나 팔에 단 서보를 움직이는 시험은 바나나 플러그로 만든 전용 전원선으로 한다.
- 서보에는 링크나 팔 부품을 달지 않고 책상 위에 둔다. 혼은 달려 있어도 된다.
- 테이프와 네임펜: 클립을 책상에 붙이고, ID를 바꾼 서보에 번호를 적어 붙인다.

### 순서

처음에는 서보 하나만 이어 ID를 하나씩 바꾸고, 다 바꾼 뒤에 7개를 이어 잰다. 처음 전원을 넣을 때 서보가 하나라 문제가 생겨도 그 하나에서 끝나고, 이전 프로젝트의 ID가 겹쳐 있어도 상관없고, 7개를 잇는 일은 한 번이면 된다. 서보마다 ID를 바꾸기 전의 덤프는 `set-id`가 기록에 남긴다 (우리가 EEPROM을 쓰기 전으로 되돌릴 자리).

단계마다 사용자가 사진을 보내면 Claude가 맞는지 보고 다음으로 넘어간다. 1은 점퍼 B, 선 색과 나사 단자, 클립 거리, 빼 둔 빨강 플러그를 보고, 2는 가변 전원 화면(12.0 V, C.C 꺼짐)을 본다.

1. 서보 하나 잇기 (가변 전원을 켜기 전에)
   - 서보 하나만 어댑터의 단자 1에 꽂는다. 커넥터는 한쪽으로만 들어가니 억지로 넣지 않는다.
   - 전원선을 어댑터의 나사 단자에 물린다 (빨강 DC+, 검정 DC−). 가변 전원에는 − 플러그만 꽂고 + 플러그는 빼 둔다.
   - 어댑터 USB를 PC에 꽂는다.
2. 전원 넣기: 전류 상한은 3 A로 맞춰 둔다. 화면에 상한이 보이지 않아서 클립을 서로 물려 맞춘다 (방법은 [hardware.md](hardware.md#전원), 2026-11-11에 맞춤). 가변 전원을 켜고 화면에서 12.0 V를 본다. 그다음 + 플러그를 꽂는다. C.C 표시등이 켜지면 전류 상한에 걸린 것이니 바로 + 플러그를 뺀다. 타는 냄새가 나도 바로 뺀다. 둘 다 정상이면 일어나지 않고, 선이 잘못 이어졌을 때의 신호다. 꽂은 뒤 화면의 전류를 읽어 알린다. 서보 하나가 토크 없이 쉴 때 먹는 전류이고, [0016](decisions/0016-servo-power.md)의 버팀 전류 계산에서 빼 두었던 값이다.
3. 포트 확인: `uv run python -m horilab_servo ports`. 어댑터 포트에 "← 서보 어댑터"가 붙는다. 이 표시가 하나뿐이면 다음 명령들이 그 포트를 저절로 쓴다.
4. ID 바꾸기 (서보마다 되풀이): ID는 관절 번호다 ([0024](decisions/0024-servo-bus.md)). STS3250은 3, STS3215 다섯은 1, 4, 5, 6, 11(그리퍼)이고, 남는 STS3215 하나는 예비 20이다. 펌웨어가 다른 STS3215가 보이면 그것을 예비로 돌린다. 나머지는 어느 서보를 어디에 써도 된다.
   1. `uv run python -m horilab_servo set-id --to 3`으로 할 일을 본다 (15초쯤 찾는다). 서보 1개가 보여야 하고, 모델과 펌웨어도 같이 나온다. 확인한 뒤 `--yes`를 붙여 바꾼다.
   2. 서보에 번호를 적은 테이프를 붙인다.
   3. + 플러그를 빼고 다음 서보로 바꿔 꽂은 뒤 + 플러그를 꽂는다. 7개를 다 바꿀 때까지 되풀이한다.
5. 7개 모두 잇기: + 플러그를 빼고 서보를 단자 1에 3개, 단자 2에 4개로 나눠 잇는다. 서보에는 커넥터가 두 개 있고, 한 서보에서 다음 서보로 케이블 하나씩 잇는다. + 플러그를 꽂고 화면의 전류를 다시 읽어 알린다 (서보 7개가 쉴 때).
6. 찾기: `uv run python -m horilab_servo scan` (15초쯤). 7개가 1, 3, 4, 5, 6, 11, 20으로 다 보이는지, 전압(12.0 V 가까이)을 본다. 하나라도 없으면 그 서보의 케이블을 본다.
7. 기준 덤프: `uv run python -m horilab_servo dump`. 7개의 설정이 이 기록에 남고, 다음 덤프들이 이것과 견준다. 화면의 `*`는 메모리 표의 초기값과 다른 칸이고, `!`는 같은 모델끼리 다른 칸이다. 메모리 표 밖(71~127번)도 읽히면 같이 남는다.
8. 통신 시간: `uv run python -m horilab_servo timing`으로 할 일을 보고, 확인한 뒤 `--yes`를 붙여 잰다 (1분쯤).
9. 잠금 확인: 가변 전원은 켠 채 + 플러그를 뺐다 다시 꽂는다. `dump`를 다시 뜬다. 화면 끝의 "지난 덤프와 견줌"에서 모든 서보가 "같다"면, 잠근 채 쓴 응답 지연이 전원을 끄자 사라진 것이다 (메모리 표대로다). 응답 지연이 처음부터 0이었으면 `timing`이 바꾼 것이 없어서 이것으로는 확인되지 않는다. 그때는 맨 서보 확인에서 P를 잠근 채 바꿔 보며 확인한다.
10. 끄기: 토크는 꺼져 있다. + 플러그를 빼고 가변 전원을 끈다.
11. 기록 올리기: `uv run tools/sync.py push records`.

### hori3에서 통신 시간

같은 서보 줄과 어댑터를 hori3에 USB로 옮겨 꽂고 통신 시간을 잰다. 전원은 위와 같은 순서로 넣는다.

- 처음 한 번: uv를 깔고(`curl -LsSf https://astral.sh/uv/install.sh | sh`) 레포를 받는다(`git clone https://github.com/zzingobomi/horilab.git`). uv가 맞는 Python을 알아서 받는다.
- 레포 폴더에서 `uv run --package horilab-servo python -m horilab_servo timing --yes`. 꽂힌 서보를 다 찾아서 잰다. 이 패키지의 의존성(공식 SDK, pyserial)만 깐다.
- 포트를 열지 못하면(권한) 사용자를 dialout 그룹에 넣고(`sudo usermod -aG dialout $USER`) 다시 로그인한다.
- 기록은 hori3의 레포 폴더 `records/servo/` 아래에 생긴다. PC의 같은 자리로 가져와(scp) 올린다. 파이가 직접 올리는 것은 컨트롤러를 파이에 배포할 때 만든다 ([0026](decisions/0026-pi-runtime-deploy-records.md)).

### 볼 것과 적을 곳

- 찾기와 덤프: [0024](decisions/0024-servo-bus.md)의 "실물로 확인할 것"을 본다. 모델 번호와 펌웨어 버전이 모델끼리 같은지([hardware.md](hardware.md#서보-설정-주의)), 7번(공장값 250이면 500 µs, LeRobot은 0으로 바꾼다), P(LeRobot은 16으로 바꾼다), 위치 오프셋과 각도 한계(LeRobot 보정이 쓴다), Phase, 최대·최소 입력 전압([status.md](status.md)의 12.0 V 여유), 표 밖에서 0이 아닌 칸. 결과는 [hardware.md](hardware.md)와 0024에 적는다.
- 통신 시간: 응답 지연 0에서 실패가 없는지, 한 박자(실행 루프가 주기마다 하는 동기 쓰기와 동기 읽기)의 중간과 p99가 10 ms(100 Hz) 안에 얼마나 여유 있게 드는지, 잰 값과 선로 계산의 차이(USB와 운영체제 몫)를 본다. 실행 루프 주기를 정할 때 쓰고([0009](decisions/0009-control-architecture.md)), hori3 실행 루프 부하 시험에 버스 시간으로 넣는다 ([0026](decisions/0026-pi-runtime-deploy-records.md)의 미리 재기). Python이라 어림값이고, Rust의 값은 0024 만드는 순서 6번에서 다시 잰다.
- 잠금: 7번이 돌아왔는지. 결과는 0024에 적는다.

### 새 서보 (ST-3120)

다른 서보를 빼고 혼자 꽂아, 아무것도 쓰기 전에 `scan`과 `dump`를 뜬다. 새 서보의 덤프가 그 모델의 공장값이다. 이어서 혼자 꽂은 채 `set-id --to 2`로 ID를 2(어깨)로 바꾼다. 메모리 표의 ID 초기값이 1이라 J1과 겹치니, 바꾸기 전에는 다른 서보와 같은 버스에 두지 않는다. 처음 보는 모델 번호는 [hardware.md](hardware.md#서보-사양)의 표와 `registers.py`, `registers.rs`의 `MODELS`에 넣고, 그 덤프로 로봇 설정에 `[models.ST-3120.registers]`를 적는다 (Claude).

## 값 적용

서보의 EEPROM을 로봇 설정([data/robot.toml](../data/robot.toml))에 맞춘다. 서보에 남은 값에 기대지 않으려는 것이다 ([0024](decisions/0024-servo-bus.md)). 명령은 컨트롤러(`crates/controller`)에 있고, 레포 루트에서 돌린다.

- `cargo run -p horilab-controller -- apply --port <포트>`: 로봇 설정의 관절마다 서보를 찾아 모델 번호를 맞춰 보고, 덤프를 읽어 로봇 설정과 다른 칸을 보여 준다. 읽기만 한다. 포트 목록은 `cargo run -p horilab-controller -- ports`이고, `--joint j3`처럼 관절을 고를 수 있다.
- 같은 명령에 `--yes`를 붙이면 다른 칸만 EEPROM에 쓰고 다시 읽어 확인한다. 토크가 켜져 있으면 쓰지 않고, 서보는 움직이지 않는다. 쓰기 전후의 덤프와 그때의 로봇 설정이 `records/servo/<날짜시각>_apply-<컴퓨터>/meta.json`에 남는다. Claude는 `--yes`로 돌리기 전에 확인을 받는다.
- 할 때: 원판이나 링크를 달기 전, 팔에서 고른 게인을 구울 때, 영점을 잰 뒤(서보 각도 한계가 소프트 한계로 바뀐다), 서보를 갈아 끼웠을 때.
- J3(STS3250)은 로봇 설정의 값이 첫 덤프와 같아서, 지금은 쓸 칸이 없다 (2026-11-12, 첫 덤프로 견줌).

## 맨 서보 확인

팔을 처음 움직이기 전에, 로봇에 달지 않은 예비 서보 하나로 서보 프로그램이 위치 경계, 각도 한계, 보호, 끊김에서 어떻게 하는지 본다. 무엇을 왜 보는지는 [0024](decisions/0024-servo-bus.md)의 맨 서보 확인 프로그램과 [0027](decisions/0027-general-purpose-review.md)의 "실물로 미리 확인할 것"에 있고, 결과(2026-11-13)는 0024의 "맨 서보 확인 결과"에 있다. 명령은 컨트롤러에 있고 레포 루트에서 돌린다. 15분쯤 걸린다.

- 서보가 움직인다. 예비 서보 ID(20~29)만 받는다. 토크 20 %로 느리게 움직이고, 손으로 붙잡는 단계는 토크 5 %다.
- 서보 설정(P 게인, 각도 한계, 위치 오프셋, 전압 하한, 힘을 빼는 조건, 과부하 보호)은 잠근 채 잠깐 바꾸고, P 게인 말고는 그 단계 끝에 되돌린다. 잠근 채 바꾼 값은 서보 전원을 끄면 사라진다. 중간에 끊겼으면 + 플러그를 뺐다 꽂는다.
- 명령은 Claude가 돌리고 기록도 Claude가 읽는다. 사용자는 손으로 하는 일(꽂기, 혼 잡기, 전압 손잡이)만 한다. `check --yes`는 확인을 받은 뒤 사용자가 보는 창으로 띄운다. 혼을 잡고 놓을 때와 전압을 바꿀 때 사용자가 Enter를 누르기 때문이다.
- 버티는지를 손으로 보지 않는다. 맨 혼은 서보 전원이 없어도 손가락으로 돌아가지 않아서, 손 느낌으로는 토크가 켜진 것과 기어의 마찰을 가를 수 없다. 서보에서 읽은 값으로 본다.
- 한 단계만 다시 볼 때는 `--only state,offset`처럼 단계 이름을 고른다.
- 기록은 `records/servo/<날짜시각>_check-<컴퓨터>/`(`meta.json`의 results, `samples.csv`, `events.csv`)와 `<날짜시각>_check-state-<컴퓨터>/`에 남는다.

### 준비

- 예비 STS3215(ID 20) 하나만 어댑터 단자 1에 꽂는다. 혼은 단 채로 두고 아무것도 달지 않는다. 손으로 붙잡는 단계가 있어서 서보는 책상에 고정하지 않는다.
- 전원은 첫 연결과 같다. 악어 클립이어도 된다 (위 [준비](#준비)). 전류 상한은 3 A다.
- 가변 전원은 화면이 보이고 손잡이에 손이 닿는 곳에 둔다. 전압 단계에서 전압 손잡이를 돌린다.
- 이 PC에 Rust가 없으면 [setup.md](setup.md#8-rust)대로 깐다. 처음 돌릴 때는 컨트롤러를 빌드하느라 1~2분 걸린다.

### 순서

1. 전원 넣기 (사용자): 첫 연결의 2와 같다. 화면에서 12.0 V를 본 뒤 + 플러그를 꽂는다.
2. 응답 보기 (Claude): `cargo run -p horilab-controller -- ports`로 포트를 찾고, `cargo run -p horilab-controller -- check --port <포트> --id 20`으로 서보를 한 번 읽는다. 서보는 움직이지 않는다.
   - 응답하지 않으면 + 플러그, 서보 선, USB를 보고, `uv run python -m horilab_servo scan`으로 같은 서보가 찾아지는지 본다.
   - 포트를 열지 못하면(장치가 작동하지 않는다는 오류) 어댑터의 USB를 뺐다 꽂는다 (2026-11-13에 이렇게 풀렸다).
3. 확인 (창): 확인을 받고 같은 명령에 `--yes`를 붙여 창으로 띄운다. 사용자는 창의 말을 따른다:
   - 속도부터 위치 오프셋까지는 서보가 혼자 돈다. 손대지 않고, 혼에 손이나 선이 걸리지 않게만 둔다.
   - 과부하 보호 1, 2: 한 손으로 서보 몸통을 잡고, 다른 손 엄지와 검지로 혼 둘레를 꽉 잡은 뒤 Enter. 서보가 3초 동안 혼을 돌리려 한다 (혼 둘레에서 약 1.5 kgf). "이제 혼을 놓고 Enter"가 나오면 놓고 Enter. 손이 미끄러져 혼이 돌아도 괜찮다. 건너뛰려면 s.
   - 전압 보호: 전압 손잡이의 테이프를 떼고 Enter. 손잡이를 천천히 왼쪽으로 돌려 10.0 V 밑으로 내린다 (9.0 V 밑으로는 내리지 않는다). "전압 비트가 켜졌다"가 나오면 오른쪽으로 돌려 12.0 V로 맞추고 Enter. 건너뛰려면 s.
   - 통신이 끊겨 멈추면 선과 전원을 보고 Enter. 그만두려면 q.
4. 끊겼을 때 (사용자가 하고 알리면 Claude가 읽는다): 끝나면 서보는 토크가 켜진 채 가운데에 있다. 넷 모두 `cargo run -p horilab-controller -- check-state --port <포트> --id 20 --situation <번호>`이고, 서보는 움직이지 않는다.
   1. 그대로 (프로그램을 끈 뒤).
   2. 어댑터의 USB를 뽑았다가 다시 꽂은 뒤. 포트 이름이 바뀌었으면 `ports`로 본다.
   3. + 플러그를 뽑은 채. 서보가 응답하지 않으면 맞다. 응답하면 USB 전기로 서보가 살아 있는 것이다.
   4. + 플러그를 다시 꽂은 뒤. 토크가 꺼져 있고, P 게인과 EEPROM이 확인을 시작할 때와 같아야 한다.
5. 끄기 (사용자): + 플러그를 빼고 가변 전원을 끈다. 전압 손잡이에 테이프를 다시 붙인다.
6. 기록 (Claude): `uv run tools/sync.py push records`로 올리고, 결과를 0024와 [hardware.md](hardware.md)에 적는다.

### 볼 것

- 경계와 여러 바퀴: 위치 모드가 0/4095 경계를 넘는지, 각도 한계를 0과 0으로 두면 한 바퀴 밖으로 가는지. J1의 범위와 경계 여유를 정하는 데 쓴다 ([0024](decisions/0024-servo-bus.md)의 J1 문단).
- 한계 밖에서 토크 켜기: 지금 위치가 각도 한계 밖일 때 토크를 켜면 서보가 한계까지 스스로 움직이는지, 그 자리에서 버티는지. 기계 멈춤(163°)이 프로그램 한계(160°)보다 밖에 있어서, 팔을 멈춤까지 밀어 둔 채 켜면 생기는 상황이다 ([0029](decisions/0029-joint-parts.md)).
- 위치 오프셋: 오프셋을 바꾸면 읽는 위치가 그만큼 옮겨지는지, 0/4095 경계도 같이 옮겨지는지. 관절마다 경계 여유를 얼마로 둘지와, 영점을 혼 톱니로 맞출지 오프셋으로 잡을지를 정하는 데 쓴다 ([0024](decisions/0024-servo-bus.md)의 UR식 관절의 영점과 경계).
- 과부하 보호: 힘을 빼는 조건을 켠 것과 끈 것에서 각각 보호에 들어간 시각, 토크가 꺼졌는지, 보호 뒤 부하가 버티는 토크(2 %)로 줄었는지, 놓은 뒤 저절로 풀렸는지. 전압 보호: 전압 비트가 켜진 전압, 토크가 꺼졌는지, 12 V로 돌아온 뒤 토크가 돌아왔는지. 둘로 로봇 설정의 보호 조건을 다시 정한다 ([status.md](status.md)의 열린 질문).
- 끊김: 프로그램이 꺼지거나 USB가 빠져도 버티는지, 전원이 돌아오면 토크가 꺼져 있는지 ([0009](decisions/0009-control-architecture.md)의 끊김 행).
- 잠금: 각도 한계를 잠근 채 바꾸자 바로 그 한계에서 섰는지, 전원을 껐다 켠 뒤 P 게인과 EEPROM이 처음과 같은지.
- 속도 단위(50 step/s인지 1 step/s인지)와 현재 전류의 부호.
