# 서보 준비

제작 로드맵 2단계(서보와 연결 준비)의 순서와 명령이다. 지금은 첫 연결(찾기, 덤프, 통신 시간)만 있다. ID 바꾸기와 값 적용은 컨트롤러의 서보 준비 명령([0024](decisions/0024-servo-bus.md) 만드는 순서 3번)을 만들 때 더한다.

## 첫 연결

서보를 처음 어댑터에 이어, 서보에 지금 무엇이 들어 있는지 남기고(덤프) 통신 시간을 잰다 ([0024](decisions/0024-servo-bus.md)의 영향). 명령은 Python 기준 구현(`packages/servo`)에 있다.

- 서보를 움직이지 않는다. 목표 위치도 쓰지 않는다. 각도 한계 밖에 놓인 서보에 목표를 쓰면 한계까지 움직일 수 있어서다.
- `scan`과 `dump`는 읽기만 한다. `timing`은 두 가지를 쓴다. 동기 쓰기 자리에 토크 제한(RAM)으로 읽은 값을 그대로 쓰고, 응답 지연(7번)은 잠근 채 0으로 바꿔 한 번 더 잰다. 서보 전원을 껐다 켜면 둘 다 처음 값으로 돌아간다. 그래서 `timing`은 `--yes`를 붙여야 돌고, Claude는 돌리기 전에 확인을 받는다.
- 기록은 `records/servo/<날짜시각>_<명령>-<컴퓨터>/`에 남는다: `meta.json`(조건, 코드 커밋, 서보마다의 덤프나 통신 시간 요약)과, `timing`은 `samples.csv`(잰 것 하나하나)도 남긴다.
- 명령은 Claude가 돌리고 출력을 읽는다. 기록은 명령이 파일로 남겨서 숫자를 옮겨 적지 않는다. 사용자는 손으로 하는 일을 하고, 프로그램이 볼 수 없는 것을 알려 준다: 꽂은 서보 수, 가변 전원 화면의 전압과 전류, C.C 표시등, 서보 LED가 깜박이는지, 타는 냄새 같은 이상.

### 준비

- 서보: 가진 STS3215 여섯과 STS3250 하나. 20 cm 서보 케이블이 6개뿐이면 서보 6개로 잰다. 버스 시간은 서보 수에 비례하므로 7개는 셈으로 늘리고, 케이블이 더 오면 다시 잰다.
- 서보 어댑터 (점퍼 B, [hardware.md](hardware.md#서보-어댑터))와 USB-C 케이블. 데이터가 되는 케이블이면 길이는 상관없다. 충전만 되는 케이블이면 `ports`에 어댑터가 보이지 않는다.
- 가변 전원과 전용 전원선. 가변 전원 쪽은 바나나 플러그, 어댑터 쪽은 나사 단자다 ([hardware.md](hardware.md#전원)).
- 바나나 플러그가 오기 전에는 첫 연결만 가변 전원의 리드선(가변 전원 쪽 바나나 플러그, 반대쪽 악어 클립)으로 해도 된다 ([0016](decisions/0016-servo-power.md)의 바뀐 점).
  - 어댑터 나사 단자에 빨강·검정 선을 물리고(빨강 DC+, 검정 DC−), 그 선의 벗긴 끝에 같은 색 클립을 문다. 클립은 피복이 아니라 구리를 물게 하고, 살짝 당겨 빠지지 않는지 본다.
  - 클립은 어댑터에서 한 뼘 이상 떨어지게 둔다. 빠진 클립이 어댑터에 닿으면 12 V가 USB 쪽으로 들어가 어댑터나 PC의 USB 포트가 망가질 수 있다. 두 클립은 서로 닿지 않게 떼어 각각 테이프로 책상에 붙인다.
  - 클립은 + 플러그를 뺐을 때만 물리고 뗀다. 켜고 끄는 것은 빨강 리드선의 바나나 플러그를 가변 전원의 + 단자에서 빼고 꽂아서 한다 (아래 순서 그대로).
  - 토크를 켜는 시험(관절 시험부터)은 바나나 플러그로 만든 전용 전원선으로 한다.
- 서보에는 아무것도 달지 않고 책상 위에 둔다.

### 순서

단계마다 사용자가 사진을 보내면 Claude가 맞는지 보고 다음으로 넘어간다. 1은 점퍼 B, 선 색과 나사 단자, 클립 거리, 빼 둔 빨강 플러그를 보고, 2는 가변 전원 화면(12.0 V, C.C 꺼짐)을 본다.

1. 잇기 (가변 전원을 켜기 전에)
   - 서보들을 어댑터의 서보 단자 두 개에 나눠 잇는다 (예: 한쪽에 3개, 다른 쪽에 4개). 서보에는 커넥터가 두 개 있고, 한 서보에서 다음 서보로 케이블 하나씩 잇는다. 커넥터는 한쪽으로만 들어가니 억지로 넣지 않는다.
   - 전용 전원선을 어댑터의 나사 단자에 물린다 (빨강 DC+, 검정 DC−). 가변 전원에는 − 플러그만 꽂고 + 플러그는 빼 둔다.
   - 어댑터 USB를 PC에 꽂는다.
2. 전원 넣기: 가변 전원을 켜고 화면에서 12.0 V와 전류 상한 3 A를 본다. 그다음 + 플러그를 꽂는다. C.C 표시등이 켜지면 전류 상한에 걸린 것이니 바로 + 플러그를 뺀다. 타는 냄새가 나도 바로 뺀다. 둘 다 정상이면 일어나지 않고, 선이 잘못 이어졌을 때의 신호다. 꽂은 뒤 화면의 전류를 읽어 알린다. 서보가 토크 없이 쉴 때 먹는 전류이고, [0016](decisions/0016-servo-power.md)의 버팀 전류 계산에서 빼 두었던 값이다.
3. 포트 확인: `uv run python -m horilab_servo ports`. 어댑터 포트에 "← 서보 어댑터"가 붙는다. 이 표시가 하나뿐이면 다음 명령들이 그 포트를 저절로 쓴다.
4. 찾기: `uv run python -m horilab_servo scan` (15초쯤). 찾은 수가 꽂은 수와 같은지, 모델, 펌웨어, 전압(12.0 V 가까이)을 본다. 수가 모자라거나 "응답이 깨진 ID"가 나오면 같은 ID의 서보가 있을 수 있다. 그때는 서보를 하나씩 꽂아 ID를 확인하고, ID 바꾸기를 어떻게 할지 정한다.
5. 덤프: `uv run python -m horilab_servo dump --ids 1-7` (찾은 ID로). 이것이 첫 덤프이고, 우리가 EEPROM을 쓰기 전으로 되돌릴 자리다. 화면의 `*`는 메모리 표의 초기값과 다른 칸이고, `!`는 같은 모델끼리 다른 칸이다. 메모리 표 밖(71~127번)도 읽히면 같이 남는다.
6. 통신 시간: `uv run python -m horilab_servo timing --ids 1-7`로 할 일을 보고, 확인한 뒤 `--yes`를 붙여 잰다 (30초쯤).
7. 잠금 확인: 가변 전원은 켠 채 + 플러그를 뺐다 다시 꽂는다. `dump --ids 1-7`을 다시 뜬다. 화면 끝의 "지난 덤프와 견줌"에서 모든 서보가 "같다"면, 잠근 채 쓴 응답 지연이 전원을 끄자 사라진 것이다 (메모리 표대로다). 응답 지연이 처음부터 0이었으면 `timing`이 바꾼 것이 없어서 이것으로는 확인되지 않는다. 그때는 관절 시험에서 P를 잠근 채 바꿔 볼 때 확인한다.
8. 끄기: 토크는 꺼져 있다. + 플러그를 빼고 가변 전원을 끈다.
9. 기록 올리기: `uv run tools/sync.py push records`.

### hori3에서 통신 시간

같은 서보 줄과 어댑터를 hori3에 USB로 옮겨 꽂고 6을 한다. 전원은 위와 같은 순서로 넣는다.

- 처음 한 번: uv를 깔고(`curl -LsSf https://astral.sh/uv/install.sh | sh`) 레포를 받는다(`git clone https://github.com/zzingobomi/horilab.git`). uv가 맞는 Python을 알아서 받는다.
- 레포 폴더에서 `uv run --package horilab-servo python -m horilab_servo timing --ids 1-7 --yes`. 이 패키지의 의존성(공식 SDK, pyserial)만 깐다.
- 포트를 열지 못하면(권한) 사용자를 dialout 그룹에 넣고(`sudo usermod -aG dialout $USER`) 다시 로그인한다.
- 기록은 hori3의 레포 폴더 `records/servo/` 아래에 생긴다. PC의 같은 자리로 가져와(scp) 올린다. 파이가 직접 올리는 것은 컨트롤러를 파이에 배포할 때 만든다 ([0026](decisions/0026-pi-runtime-deploy-records.md)).

### 볼 것과 적을 곳

- 찾기와 덤프: [0024](decisions/0024-servo-bus.md)의 "실물로 확인할 것"을 본다. 모델 번호와 펌웨어 버전이 모델끼리 같은지([hardware.md](hardware.md#서보-설정-주의)), 7번(공장값 250이면 500 µs, LeRobot은 0으로 바꾼다), P(LeRobot은 16으로 바꾼다), 위치 오프셋과 각도 한계(LeRobot 보정이 쓴다), Phase, 최대·최소 입력 전압([status.md](status.md)의 12.0 V 여유), 표 밖에서 0이 아닌 칸. 결과는 [hardware.md](hardware.md)와 0024에 적는다.
- 통신 시간: 응답 지연 0에서 실패가 없는지, 한 박자(실행 루프가 주기마다 하는 동기 쓰기와 동기 읽기)의 중간과 p99가 10 ms(100 Hz) 안에 얼마나 여유 있게 드는지, 잰 값과 선로 계산의 차이(USB와 운영체제 몫)를 본다. 실행 루프 주기를 정할 때 쓰고([0009](decisions/0009-control-architecture.md)), hori3 실행 루프 부하 시험에 버스 시간으로 넣는다 ([0026](decisions/0026-pi-runtime-deploy-records.md)의 미리 재기). Python이라 어림값이고, Rust의 값은 0024 만드는 순서 6번에서 다시 잰다.
- 잠금: 7번이 돌아왔는지. 결과는 0024에 적는다.

### 새 서보 (ST-3120)

다른 서보를 빼고 혼자 꽂아, 아무것도 쓰기 전에 `scan`과 `dump`를 뜬다. 새 서보의 덤프가 그 모델의 공장값이다. 메모리 표의 ID 초기값이 1이라 가진 서보와 겹칠 수 있으니, ID를 바꿀 때까지 다른 서보와 같은 버스에 두지 않는다. 처음 보는 모델 번호는 [hardware.md](hardware.md#서보-사양)의 표와 `registers.py`의 `MODELS`에 넣는다.
