# 진행 상황

마지막 갱신: 2026-11-11

## 지금 단계

**제작 로드맵: 0단계(공차 시험편, 서보 실측)를 마무리하며 2단계(서보와 연결 준비)와 3단계(관절 하나 시험)를 준비한다.** 기반 결정(문서 체계, 아키텍처, 폴더 구조, 개발 환경, 코드·테스트·git 규칙, 관절 구동, 손목 형식, 정밀도 기준, 작업 공간, 관절 구조, 골격)과 1단계(골격 설계)는 끝났다. 결정 기록은 [decisions/](decisions/)에 있다.

- 폴더 구조, Python 환경, 도구 설정, 구조 테스트는 해 두었다.
- 골격 설계에 쓸 검토 도구를 만들었다: 로봇 기술 → FK, MJCF(막대 모델), URDF, 해석적 IK, 버팀 토크, 백래시 끝점 오차 (`packages/design`). 관절 구동([0011](decisions/0011-joint-drives.md))과 손목 형식([0013](decisions/0013-wrist-type.md))을 이것으로 정했다.
- 치수 값 파일의 뼈대를 만들었다 ([0006](decisions/0006-data-and-pipeline.md)): `params/arm.toml`, `params/servos.toml`, `data/measured.toml`을 읽어 검사하고 로봇 기술로 바꾼다 ([software.md](software.md#하나의-치수-값에서-모든-결과물을)).
- 출력 설정을 정했다 (구조 부품은 0.20mm Strength, [manufacturing.md](manufacturing.md#출력-설정)). 1차 공차 시험편(M3 볼트 구멍, 너트 홈)을 만들었다 (`build/coupons/`).
- 서보 세 종의 공식 도면을 찾아 기구 치수를 정리했다 ([hardware.md](hardware.md#기구-치수)). 2차 공차 시험편(STS 서보 틀, 혼 자리)도 도면 치수로 만들었다.
- 박스 쌓기 배치를 정했다 ([0014](decisions/0014-workspace-layout.md)): 집는 자리와 팔레트는 로봇 양쪽 앞, 박스 자리는 반지름 25 cm 안. 대표 작업은 크기가 다른 박스를 섞어 쌓는 랜덤 팔레타이징이다 ([goals.md](goals.md#대표-작업), 11/11): 정한 규격 5~7가지의 박스가 규격마다 몇 개인지 모르게 아무렇게나(구멍은 위로) 놓이면, 카메라로 보고 쌓는 법을 정해 쌓는다. 규격은 위에서 본 크기가 서로 다르게 골라 기둥의 USB 카메라 하나로 가른다. 규격은 그리퍼를 설계하기 전에 정하고, 그전까지 시험과 검토는 40 mm 정육면체로 한다.
- 관절 구조를 정했다 ([0015](decisions/0015-joint-structure.md)): J2~J6는 ㄷ자 브래킷이 서보의 출력 혼과 뒷면 혼을 잡고, J1은 6806 베어링 두 개를 띄워 받친다. 영점은 지름 3 mm 강철 핀으로 잡는다.
- 출력 전 확인 규칙을 정했다 ([design.md](design.md#출력-전-확인)). 그 계산 검사로 실제 서보 외형과 관절 구조를 넣은 골격 배치를 검토하고 (`studies/packaging.py`) 골격을 정했다 ([0017](decisions/0017-skeleton.md)): 어깨 높이 160, 위팔 220, 아래팔 180, 손목 오프셋(0019에서 63 · 63 · 50 mm로 늘렸다), 관절 범위, 포인터 시험 자리. 링크 길이는 처음에 박스 자리에 맞춰 골랐다가, 로봇의 작업 범위(서보가 버티는 반지름 안: 반지름 16~30 cm, 높이 2~18 cm)에서 다시 골랐다 (`studies/reach.py`). 고른 골격은 서보 부담 내역, 가속 여유, 세 가지 특이점, 1 cm 격자와 직선 경로로 더 확인했다. STS 서보는 실물을 재서 외형을 고치고 검사를 다시 돌렸다 (결정은 그대로, [hardware.md](hardware.md#기구-치수)).
- D405의 공식 사양(고정 구멍, 커넥터, 시야, 해상도별 최소 거리)을 확인했다 ([hardware.md](hardware.md#d405)). 카메라 자리를 정했다 ([0018](decisions/0018-camera-mounts.md)): D405는 손목에, USB 카메라는 책상의 카메라 기둥에 고정한다. 기둥 자리는 시야, 작업 자세, 캘리브레이션 자세를 계산해 골랐다 (`studies/cameras.py`).
- 부품 설계 전에 다른 데스크톱 로봇팔과 MakerWorld 모델을 조사해, 가져올 점과 피할 것, 협동로봇처럼 보이게 하는 외형을 정리했다 ([references.md](references.md)). 그 결과로 출력 전 확인에 링크·브래킷 휨 계산과 조립 순서 확인을 더했다 ([design.md](design.md#출력-전-확인)).
- 외형을 UR식으로 정했다 ([0019](decisions/0019-ur-look.md), `studies/covers.py`): 관절마다 축을 감싸는 원통(가운데 고리는 부모 링크, 양 끝 뚜껑은 자식 링크), 관 링크, 손목 원통 사이의 목, D405 받침판. 원통이 손목에 다 들어가도록 손목 오프셋을 63 · 63 · 50 mm로 늘렸다. 버팀 토크는 정격의 0.73배 안이고, 형상에 없는 무게(케이블, 나사)는 플랜지 기준 약 107 g까지 여유가 있다. 링크 휨 계산도 이 검토에 넣었다.
- 관절 하나 시험을 팔꿈치(J3)로 정하고 부품과 시험대를 설계했다 ([0021](decisions/0021-elbow-joint-test.md), `parts/elbow.py`, `parts/joint_test.py`). 실제 부품으로 그려 보니 개념 형상으로는 뒷면 커넥터와 영점 핀 자리가 맞지 않아서, 서보 집이 서보를 감싸고 혼마다 원판을 다는 구조로 바꿨다. 출력 파일은 `uv run python -m horilab_design.parts.joint_test`가 만든다.
- 첫 그리퍼를 평행 그리퍼로 정했다 ([design.md](design.md#도구-순서)). 박스 윗면 구멍 안을 잡아 박스를 붙여 쌓는다 ([0014](decisions/0014-workspace-layout.md)). 흡착은 나중이다 ([0020](decisions/0020-suction-gripper.md)). 그리퍼 교체부 첫 버전은 맞춤 핀 2개와 손나사 2개로 정했다 ([design.md](design.md#그리퍼-교체-구조)). 색은 몸통 흰색, 나머지(뚜껑, 브래킷·서보 자리, 베이스, 그리퍼) 검정으로 정했다 ([manufacturing.md](manufacturing.md#색)).
- 시험 기록과 PC 사이 데이터 넘기기를 정했다 ([0022](decisions/0022-records-and-sync.md)). 실물 실행의 기록은 실물이 없는 PC에서도 분석할 수 있게 남기고, git에서 뺀 데이터 폴더는 rclone으로 구글 드라이브에 레포와 같은 경로로 비춘다. 올리고 받는 명령(`tools/sync.py`)을 만들고, 로그인에 쓸 구글 앱을 만들어 두 PC(실물이 있는 PC와 없는 PC)에서 로그인했다.
- 서보 버스(컨트롤러의 맨 아래층)를 정했다 ([0024](decisions/0024-servo-bus.md)): 메모리 표, 서보마다 확인하는 동기 읽기, EEPROM 쓰기 절차, 소프트웨어 영점, 기록 형식. 만드는 순서 1번(메모리 표, 서보 버스, 가짜 서보, 테스트)을 공식 SDK 위에 Python으로 먼저 만들었다 (`packages/servo/src/horilab_servo/feetech/`). 이것은 기준 구현으로 남는다.
- PC 없이도 로봇을 쓰기로 했다 ([0025](decisions/0025-controller-on-pi.md)). 컨트롤러는 로봇 옆 컨트롤러 파이에서 돌고 Rust로 짠다. 파이는 로봇을 쓸 때만 켜고, 안 쓸 때는 멀티탭까지 끈다 ([0026](decisions/0026-pi-runtime-deploy-records.md)의 7). 카메라는 다른 파이, PC는 켜져 있을 때 붙는 손님(개발, 경로 계획, 시뮬레이션, 비전)이다. 단계는 관절 하나 시험(PC에서 돌림) → 팔 움직이기(파이 배포, PC 시뮬레이션 컨트롤러) → PC 없이 쓰기(경로 계획을 파이로)다.
- 로봇 컨트롤러 리서치 네 주제(산업용 컨트롤러, 데스크톱·오픈소스 팔, 전송 방식, 시뮬레이션 연결과 파이용 계획 라이브러리)를 마쳤다 ([controller-research.md](controller-research.md)). 0023의 정할 것마다 추천을 적었고, 0025에 시뮬레이션 연결과 경로 계획 추천을 적었다. Rust 서보 라이브러리(rustypot)가 이미 있어서, 프로토콜을 직접 짤지는 그것을 평가한 뒤 정한다.
- 실물이 있는 PC에서 파이 세 대, NAS, 그 PC, 집 네트워크를 확인하고 소프트웨어를 올렸다 (2026-11-10, [hardware.md](hardware.md#가진-것)). 파이는 우분투 패키지와 커널을, NAS는 DSM 7.2.2와 패키지를 올리고 Docker를 Container Manager로 바꿨다. 이어서 남은 리서치(파이 컨트롤러의 실행 환경·빌드·배포·기록, NAS 쓸 자리)를 마치고 ([controller-research.md](controller-research.md) 5·6절) 추천을 검토를 거쳐 [0026](decisions/0026-pi-runtime-deploy-records.md)으로 정했다. 그에 맞춰 [0009](decisions/0009-control-architecture.md)의 다시 켜짐 규칙을 고치고(컨트롤러만 다시 켜질 때와 서보 전원이 꺼졌다 켜질 때를 나눔) 관절 시험에 끊김 확인을 더했다.
- 로봇 컨트롤러와 응용의 경계를 정했다 ([0023](decisions/0023-robot-controller.md)). 산업용처럼 컨트롤러(IK, 이동 명령과 블렌드, 안전, 조종권, 조그, 티칭, 그리퍼 구동)와 응용(작업 순서, 비전)을 나눈다. 컨트롤러가 펜던트 화면(HTTPS, 가진 도메인의 인증서)과 WSS API를 직접 연다. 펜던트는 파이에 꽂은 게임패드와 안드로이드 폰 브라우저이고, 집 랜 안에서 혼자 쓴다. 밖에서 들어오는 길은 만들지 않는다.
- 구현 전에 레포의 이름과 자리를 0023·0025에 맞춰 다시 정했다 ([0007](decisions/0007-repo-structure.md)). Rust는 `crates/servo`(서보 버스)와 `crates/controller`, Python 서보 기준 구현은 `packages/servo`이고, 컨트롤러 API 클라이언트는 `packages/client`로 따로 둔다. 비어 있던 `packages/control`은 지웠다. 펜던트 화면(`pendant/`), 시뮬레이션 서버(`packages/sim`), 파이 설정(`pi/`)의 자리도 정했다. 문서의 "모터 프로세스"는 "컨트롤러"(프로그램)와 "실행 루프"(그 안의 층)로 바꿔 부른다. 개발은 컨트롤러가 파이로 가도 Windows에서 한다 ([0008](decisions/0008-environment-and-packages.md)).

## 다음 할 일

- 직접: 공차 시험편. 흰색 PLA로 여섯 개를 다 뽑았고, 1차(M3 구멍과 너트 홈)와 2차(STS3215·STS3250의 서보 틀, 혼 자리) 결과는 [data/measured.toml](../data/measured.toml)에 적었다. 남은 것은 아래와 같다 (판정법은 [manufacturing.md](manufacturing.md#공차)).
  - 검정 PLA가 왔다 (11/10). 같은 시험편 12개를 검정으로 뽑아 잰다. 6806 자리와 축(`fit3_6806_`)은 베이스가 검정이라 검정으로만 잰다. 세로 핀판(3.30~3.55)과 6806 구멍판(42.0~42.5, 여섯 칸)은 11/10에 다시 만든 파일이다. 파일 목록과 판정법은 관절 시험대 3D 페이지의 "지금 할 일과 잴 것"에 있다.
  - 영점 핀 구멍(흰색)은 끝났다 (11/10): 가로 3.30 (3.25는 뻑뻑), 세로 3.35 (첫 판 3.00~3.25에는 들어가지 않았고, 새 판에서 3.30은 뻑뻑, 3.35는 조금 놂). 세로 구멍의 틈은 영점을 읽을 때 한쪽으로 붙인다 ([0024](decisions/0024-servo-bus.md)).
  - 큰 세로 구멍: 받침 기둥 위끝 고리(설계 34.8)는 34.45~34.50으로 뽑혔다 (2026-11-10, `tube_bore_mm`).
  - ST-3120이 오면 틀·혼 자리(`fit2_st3120_`)를 뽑아 끼워 본다. 시험편은 도면 치수로 미리 만들어 두었다.
- 직접: 저울이 오면 서보 무게를 잰다. ST-3120이 오면 [hardware.md](hardware.md#기구-치수)의 "실물로 잴 것"을 잰다. 예전에 산 베어링 하나의 번호나 치수도 본다.
- Claude: 배선 경로를 그린다. 서보 줄은 어댑터의 두 단자로 나누고, 구간마다 쓸 케이블은 [0016](decisions/0016-servo-power.md)에 어림해 두었다 (산 케이블로 다 된다). D405 케이블도 같은 경로로 보고, 나중의 흡착 관이 지나갈 자리는 남긴다.
- Claude: J1 베이스를 그린다. 6806 두 개와 J1 서보가 쌓여 돌림판 윗면이 93 mm가 된다 ([0015](decisions/0015-joint-structure.md)). 바깥 링 누름판과 두 베어링을 미리 눌러 주는 구조, 베어링 자리 치수(3차 시험편 결과)를 넣는다.
- Claude: 손목(J4~J6) 부품을 그릴 때도 STS 서보 뒷면의 커넥터 자리(축에서 약 10~16 mm, 뒷면 위 약 6 mm)를 비킨다. 팔꿈치는 뒷면 원판을 허브로 띄워 비켰다 ([0021](decisions/0021-elbow-joint-test.md)). 손목은 자식이 출력 쪽으로만 나가서 다른 모양이 필요하다.
- Claude: 4단계 전에 평행 그리퍼를 그린다 ([design.md](design.md#도구-순서)). 먼저 박스 규격 5~7가지(위에서 본 크기가 서로 다르고 기둥 카메라에서 헷갈리지 않게), 집는 자리 넓이, 팔레트 크기와 바닥 틀을 정한다 ([0014](decisions/0014-workspace-layout.md)의 정할 것). 박스 윗면 구멍(어림 지름 16, 깊이 12 mm) 안에서 벌려 잡는 손가락 끝과, 컵·블록을 바깥에서 잡을 열림 폭, 랙·피니언, 갈아 끼우는 PLA 손가락과 TPU 패드, D405 시야를 가리지 않는 배치를 정하고, 박스 구멍 크기를 확정한다. 무게(검토는 140 g으로 어림)를 실제 형상으로 다시 보고, 그리퍼 선이 J6에서 꼬이는 길과 플랜지에서 빼고 꽂는 자리, 색도 같이 정한다. 살 것(TPU 패드용 필라멘트, 가이드로 쇠봉이나 레일을 고르면 그것, 플랜지의 선 연결 부품)이 생기면 바로 알린다.

- 직접: 관절 하나 시험 부품은 흰색으로 다 뽑았다 (11/11, `build/joint_test/`의 8개와 흰색 핀 시험편). 흰색은 팔 부품(관절 원통 가운데 고리, 관 링크)을 뽑을 때까지 더 뽑을 것이 없다. 시험이 무엇을 어떻게 재는지, 책상 배치, 짐, 클램프, 게이지 달기, 사진은 [joint-test.md](joint-test.md)와 관절 시험대 3D 페이지에 있다.
  - 서보 집과 출력 쪽 원판에는 잰 값(핀 구멍 가로 3.30·세로 3.35, 서보 집 꽂이 34.2 mm)을 넣었다. 핀과 꽂이가 들어가는지는 조립하면서 본다. 처음 뽑은 게이지 받침은 클램프로 물 자리가 없어 쓰지 않는다 ([0021](decisions/0021-elbow-joint-test.md)의 바뀐 점).
  - 받은 것: 볼트, 다이얼 게이지 (11/10). 게이지를 새 게이지 받침의 두 집게에 끼워, 나사로 잡히는지와 잡힌 채 바늘이 부드러운지 본다 (3D 페이지의 "3D로 보기").
  - 짐으로 쓸 것: 500 ml 생수병, 끈 60 cm, 테이프, 짐을 뺄 때 받칠 책.
- Claude: Rust 컨트롤러를 시작한다 ([0025](decisions/0025-controller-on-pi.md)의 관절 하나 시험, [0024](decisions/0024-servo-bus.md)의 만드는 순서). 실물 없이 되는 일이라 어느 PC에서든 한다.
  1. Windows용 Rust: 실물이 없는 PC에는 2026-11-11에 1.99.1을 깔았다. 실물이 있는 PC는 1.80이라 `rustup update`로 올린다 ([setup.md](setup.md#8-rust)). 레포 루트에 Cargo 워크스페이스와 `crates/servo`·`crates/controller`를 만들고 ([0007](decisions/0007-repo-structure.md)), 크레이트 경계 검사(크레이트 사이 방향, 시리얼 크레이트는 servo만)를 `tests/test_structure.py`에 더하고, 도구 모음 버전 고정(`rust-toolchain.toml`), `.gitignore`의 `target/`, CLAUDE.md의 커밋 전 검사(`cargo fmt --check`, `cargo clippy`, `cargo test`), conventions.md의 Rust 규칙을 더한다 (0025의 영향).
  2. 미리 재기: TLS(0023의 HTTPS)와 시리얼 크레이트를 넣은 작은 시험 실행 파일을 PC에서 파이용으로 교차 빌드하고(cargo-zigbuild, [0026](decisions/0026-pi-runtime-deploy-records.md)의 3), hori3에서 돌려 본다. TLS 크레이트는 C 소스를 같이 빌드해서, 0026의 "C 라이브러리가 끼는 크레이트를 넣지 않는다"와 부딪히는지와 Windows에서 교차 빌드가 되는지를 여기서 본다. 막히면 WSL이 아니라 GitHub arm64 러너를 본다 ([0008](decisions/0008-environment-and-packages.md)).
  3. Rust 서보 라이브러리 rustypot을 0024의 확인 항목으로 평가해서, 그대로 쓸지 참고만 하고 직접 짤지 정한다 ([0025](decisions/0025-controller-on-pi.md)의 영향). 그 결과로 0024 만드는 순서 1번(메모리 표, 서보 버스, 가짜 서보, 테스트)을 Rust로 한다. 시험 항목은 Python 기준 구현의 테스트(`packages/servo/tests/`)와 같게 한다. 이것이 되면 가짜 서보로 hori3에서 실행 루프 부하 시험을 한다 ([0026](decisions/0026-pi-runtime-deploy-records.md)).
  4. 이어서 0024 만드는 순서 2~7번을 Rust로 한다. 다음은 로봇 설정 파일(J3부터)이다.
- 직접 + Claude: 어댑터와 서보 전원이 준비되면 Python 기준 구현으로 서보를 찾고 덤프를 뜨고 통신 시간을 잰다 (명령을 하나 더한다). 통신 시간은 팔에 쓸 서보 7개(그리퍼 포함)를 한 버스에 이어 PC와 hori3에서 잰다. 20 cm 케이블이 6~7개라 모자라면 6개로 재서 7개는 셈으로 늘리고(버스 시간은 서보 수에 비례한다), 산 케이블이 오면 다시 잰다. 첫 덤프는 SO-101에서 쓰던 상태라 공장값이 아니다. 무엇이 바뀌었는지 보고 되돌릴 자리로 남기며, 0024의 "실물로 확인할 것"을 함께 본다.
- 직접 + Claude ([0026](decisions/0026-pi-runtime-deploy-records.md)의 영향): 파이 세 대의 SD 카드 이미지는 떠 두었다 (2026-11-11, 켜진 채로 네트워크로 읽어 압축, 체크섬 확인, 실물이 있는 PC에 있다). NAS로 옮긴다. 가진 파이 세 대의 부트로더가 26.04 조건보다 옛날이라, 여분 파이 hori3의 카드를 USB 카드 리더로 PC에 꽂아 부트로더를 먼저 올리고 26.04를 깔아 시험한다. 이어서 부하를 건 지연 측정(일반 커널과 실시간 커널)을 한다 ([0026](decisions/0026-pi-runtime-deploy-records.md)의 미리 재기). NAS Cloud Sync에 구글 로그인을 한다.
- 직접 + Claude (미리 재기): 그리퍼 서보(STS3215) 하나를 멈춤에 대고, 토크 한도 몇 가지에서 쥘 때의 전류와 부하를 잰다. 그리퍼의 힘 제한과 단자 2의 전류 합([0016](decisions/0016-servo-power.md))에 쓴다. 값 적용 뒤, 그리퍼를 설계하기 전에 한다. 멈춤을 만드는 방법은 Claude가 정한다.
- 직접 + Claude (미리 재기): 펜던트의 데드맨을 만들기 전에, 쓰는 폰(안드로이드)에서 파이까지 와이파이 왕복 시간(분포와 최악)을 잰다. 데드맨이 끊겼다고 볼 시간이 여기에 기댄다. 시험 페이지는 Claude가 만든다.
- Claude: 제작 로드맵 2단계에서 서보를 다루는 프로그램은 위의 Rust 컨트롤러다. 바나나 플러그와 USB 케이블이 오기 전에 준비하고, 관절 시험에서 서보를 켜는 것은 이것이 된 뒤에 한다 ([0021](decisions/0021-elbow-joint-test.md)의 재는 것). 서보 줄은 받침 기둥 속으로 넣지 않고 관절 아래로 바로 빼서 20 cm 케이블로 어댑터에 잇는다 ([0021](decisions/0021-elbow-joint-test.md)의 영향). 기록의 형식과 표준 경로(`records/`, `videos/`)는 0024에서 정했고, 기록을 만들 때 동기화 목록(`tools/sync.py`)과 `.gitignore`에 넣는다.
- 직접: 컨트롤러 파이와 카메라 파이의 자리를 정할 때, 그 자리에 랜을 꽂을 공유기나 스위치 포트가 있는지와 케이블 수를 센다 ([0025](decisions/0025-controller-on-pi.md)의 영향). 세 대가 모두 4B 4GB인 것은 확인했다.
- 직접: 주문한 부품을 받으면 Claude에게 알려 준다 ([부품표](bom.md)의 "배송 중"). 저울이 오면 서보 무게부터 잰다.

## 제작 로드맵

이 순서로 진행한다.

0. **레포 준비**: [0007](decisions/0007-repo-structure.md)의 폴더 구조와 [0008](decisions/0008-environment-and-packages.md)의 Python 환경, 치수 값 파일의 뼈대를 만든다. SO-101에서 서보를 빼고, 서보 모델마다(STS3215, STS3250, 도착하면 ST-3120) 실제 치수와 무게를 잰다. 출력 공차 시험편을 뽑아 재서 공차 값을 정한다 (시험편 종류는 [manufacturing.md](manufacturing.md#공차)).
1. **골격 설계**: 축 배치와 링크 길이를 정한다. 관절별 토크와 오차를 계산하고, MuJoCo 막대 모델로 작업 범위, IK, 특이점을 확인한다. 이 단계에는 아직 부품 모양이 없다. 이 단계를 하는 동안 2~3단계 부품을 주문한다.
2. **서보와 연결 준비**: 서보 ID를 정하고, EEPROM 값(특히 P 게인과 불감대), 서보 자체의 보호 설정, 전압판과 펌웨어 버전을 읽어 확인하고 설정한다. 다이얼 게이지로 관절의 틈을 다시 잰다 ([0011](decisions/0011-joint-drives.md)). 서보 7개로 통신 속도를 재서 실행 루프 주기를 정한다. 컨트롤러의 실행 루프와 안전 기능을 만들고, 실물을 처음 움직이기 전에 [0009](decisions/0009-control-architecture.md)의 시험을 통과한다. 카메라 파이를 준비한다. 파이 부하는 여분 파이(hori3)에서 미리 재고, 영상 처리를 돌린 채 하는 부하 시험은 컨트롤러 파이에서 한다 ([0025](decisions/0025-controller-on-pi.md)의 영향, [0026](decisions/0026-pi-runtime-deploy-records.md)의 2).
3. **관절 하나 시험**: 서보, 반대편 받침, 마스터링 핀, 상자 링크를 넣은 관절 하나를 출력한다. 흔들림, 백래시, 처짐을 재서 이전 프로젝트보다 나은지 확인한다. 서보를 넣고 재서 서보가 읽는 각도로 서보 몫과 프레임 몫을 가르고, 프레임 몫이 크면 서보 대신 출력한 서보 모형을 넣어 프레임의 휨만 따로 잰다 ([joint-test.md](joint-test.md#나눠서-재기)). 하중을 건 채 30분 버티게 두고 서보 온도와 처짐 변화도 잰다 (PLA는 55~60°C부터 물러진다).
4. **손목과 그리퍼 교체부**를 만든다.
5. **팔 전체**를 설계하고 출력하고 조립한다.
6. **실물과 시뮬레이션 연동**: 같은 제어 코드로 실물과 시뮬레이션을 돌리고 캘리브레이션한다.

## 남은 질문

항목마다 필요해지기 전에 정한다. Claude가 근거와 함께 하나씩 제안한다.

- **관절 범위와 배선**: 서보 케이블, D405 케이블(나중에 흡착 튜브)이 회전축을 지나간다. 관절 범위와 배선 경로를 같이 정하고, 흡착 튜브와 펌프 자리는 남겨 둔다. 참고 설계에서 본 후보 ([references.md](references.md)):
  - J1에 기계 멈춤을 두어 한 바퀴 넘게 돌지 않게 한다 (PAROL6).
  - 흡착 튜브가 케이블을 잡아 주게 한다 (PAROL6).
  - 배선한 뒤 범위 끝까지 돌려 보고 덮는다 (ElRobot).
- 평행 그리퍼의 가이드 방식과 열림 폭 (첫 그리퍼). 참고 설계의 후보는 세 가지다. 어느 것이든 닫는 쪽 힘은 전류로 제한한다. 박스 윗면 구멍 안에서 벌려 잡는 힘도 같이 본다.
  - 출력 레일에서 피니언 하나가 랙 두 개를 민다 (ElRobot pgripper).
  - 지름 6 mm 봉 두 개 위로 미끄러진다 (robonine).
  - MGN7 또는 MGN9 리니어 레일 (MakerWorld, reBot).
- 제어 세부: 실행 루프 주기(서보 측정 후), 메시지와 궤적 형식(만들 때, [0023](decisions/0023-robot-controller.md)의 경계로). 구조는 [0009](decisions/0009-control-architecture.md), IK 방식은 [0008](decisions/0008-environment-and-packages.md). 이전 프로젝트 코드는 이어 쓰지 않고 새로 짠다.
- **쉬는 자세**: 안 쓸 때 멀티탭을 끄면 서보 전원도 꺼져 팔이 떨어진다. 토크 없이 팔이 받쳐지는 쉬는 자세(예: 접어서 베이스에 기대기)를 팔을 설계할 때 정한다 ([0026](decisions/0026-pi-runtime-deploy-records.md)의 7, [hardware.md](hardware.md#안전)의 접은 자세).
- **USB 카메라 하나로 하는 박스 쌓기**: 기둥의 USB 카메라만으로, 집는 자리에 아무렇게나 놓인 박스의 규격과 자리(위치, 돌아간 각도)를 찾아 쌓을 수 있는지 정한다. 집는 자리 전체와 팔레트가 시야에 드는지도 본다. 규격은 위에서 본 크기로 가른다 ([0014](decisions/0014-workspace-layout.md)). 기둥을 비스듬히 볼지, 가로 팔로 위에서 볼지도 이때 고른다 ([0018](decisions/0018-camera-mounts.md)). 기둥을 설계하기 전에 정한다. 상판이 진한 고동색 나무라 파란 박스와 밝기 차이가 작고 나뭇결이 있다. 카메라로 박스를 찾기 전에 카메라 자리에서 찍은 사진으로 대비를 보고, 모자라면 작업 자리에 밝은 회색 단색 매트를 깐다.

## 확인할 것

- 관절 하나 시험을 조립할 때: 뒷면 혼을 돌기에 무엇으로 잡는지(가운데 나사, 와셔)와 STS3250 출력 면 M2 나사 구멍 깊이를 본다. 설계는 넉넉히 해 두었다 ([0021](decisions/0021-elbow-joint-test.md)).
- 서보 사양: [hardware.md](hardware.md#서보-사양)에 정리했다. STS3250의 C001/C002 차이는 확인하지 못했다 (서보의 모델 번호 레지스터로 확인할 수 있다). ST-3120은 받으면 모델 번호 레지스터를 읽고, 혼(FT110M)과 뒷면 혼이 들어 있는지 본다. 혼이 없으면 관절 시험 전에 따로 사고, 뒷면 혼이 없으면 그 자리는 MR106ZZ로 받친다 ([0015](decisions/0015-joint-structure.md)). 치수와 무게는 사양표를 믿지 않고 실물을 잰다 (제작 로드맵 0단계).
- 예산: 30만 원 안팎이 기준이고 서보도 들어간다 ([0004](decisions/0004-purchasing.md)). 지금까지의 합과 값을 모르는 품목은 [부품표](bom.md)의 예산에 늘 나온다. 흡착 부품(약 12만~13만 원)은 나중이라 "필요해지면"으로 옮겨 예산 합에서 뺐다.
- 카메라용 파이의 pyrealsense2 설치 방법: hori2에 빌드해 둔 것을 그대로 쓸 수 있는지 먼저 보고, 안 되면 다른 후보를 시험한다 ([0007](decisions/0007-repo-structure.md)). 설치한 뒤 D405 영상을 PC로 보낼 때 해상도마다 받는 프레임 수와 끊김도 잰다. 비전 처리는 PC가 하고 카메라 파이는 보내기만 하는데, 이전 프로젝트에는 깊이 영상 8 FPS, 미리보기 5 Hz로 돌린 기록이 있다 (왜 그 값이었는지는 적혀 있지 않다).
