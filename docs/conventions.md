# 규칙

## 문서

[0002](decisions/0002-docs-system.md)에서 정했다.

### 어디에 쓰나

| 위치 | 담는 것 |
|---|---|
| README.md | 이 레포가 무엇인지, 지금 상태 한 줄, 문서 목록 |
| CLAUDE.md | 새 세션이 먼저 읽을 문서, 작업 규칙, 자주 쓰는 명령. 짧게 쓰고 자세한 건 링크한다 |
| docs/ | 실제 내용 전부. 주제마다 파일 하나로 시작하고, 커지면 그 주제만 폴더로 나눈다 |
| docs/decisions/ | 결정 기록 |
| docs-local/ | 공개하지 않는 개인 자료. git에서 제외한다. 이 폴더가 없는 PC에서도 작업이 이어져야 하므로, 작업에 꼭 필요한 정보는 여기에 두지 않는다 |

다른 프로젝트가 레포에 들어오면 팔 전용 문서(goals, background, hardware, design, manufacturing, software)는 docs/<프로젝트 이름>/ 아래로 옮기고, 나머지는 공통 문서로 둔다.

### 쓰는 법

- 본문은 한국어, 파일 이름은 영어로 쓴다.
- 결정, 근거, 사실만 쓴다. 대화 내용을 옮기거나 개인에 대한 서술을 넣지 않는다. 공개하기 애매한 내용은 docs-local/에 둔다.
- 정보는 한 곳에만 쓰고 다른 곳에서는 링크한다. 주제 문서에는 지금 어떻게 돼 있는지만 쓰고, 이유는 결정 기록으로 링크한다.
- 수치에는 단위를 붙인다.
- status.md는 지금 상태만 짧게 유지하고, 작업 단위가 끝나면 고친다. 지난 일은 git 기록과 결정 기록에 남는다.

### 결정 기록

- 고민이 필요한 결정은 하나마다 파일 하나로 남긴다: `docs/decisions/NNNN-영어-제목.md`. 당연한 관례는 기록하지 않는다.
- 상태는 제안, 채택, 대체됨 중 하나다.
- 결정을 조정할 때(순서, 라이브러리, 세부 값)는 그 기록을 고치고, 맨 아래 "바뀐 점"에 날짜와 무엇을 왜 바꿨는지 한 줄로 남긴다. 이전 내용은 git 기록에 있다. 오타나 다른 문서와 맞추는 고침은 그냥 고친다.
- 결정을 뒤집을 때만 새 기록을 쓰고, 옛 기록의 상태를 "대체됨 (NNNN)"으로 바꾼다. 주제마다 지금 유효한 기록이 하나만 있게 하려는 것이다.
- 여러 갈래를 한 번에 정할 때는 대안 비교를 표로 묶어도 된다.
- 양식:

```markdown
# NNNN. 제목

- 상태: 채택
- 날짜: YYYY-MM-DD

## 배경
무엇을 왜 정해야 했나.

## 검토한 대안
대안마다 장점과 단점.

## 결정
무엇으로 정했나.

## 근거
왜 그 대안인가.

## 영향
이 결정으로 생기는 것, 나중에 다시 볼 조건.

## 바뀐 점 (조정한 적이 있을 때만)
- YYYY-MM-DD: 무엇을 왜 바꿨나.
```

## 코드

[0010](decisions/0010-code-test-git-rules.md)에서 정했다. 도구 설정은 Python은 `pyproject.toml`, Rust는 `Cargo.toml`과 `rust-toolchain.toml`에 있다.

- **단위**: 코드는 SI(m, rad, s, kg, N·m)다. build123d로 부품을 그리는 코드만 mm다. SI가 아닌 값을 함수 인자, 반환 값, 필드로 주고받을 때는 이름에 단위를 붙인다 (`_mm`, `_deg`, `_g`). 단위는 값 파일을 읽을 때, 로봇 기술에서 부품 코드로 넘길 때, 화면·파일로 내보낼 때만 바꾼다.
- **자세**: 4×4 동차 변환 행렬(numpy)로 주고받는다. 이름은 `T_a_b`이고, b 좌표계를 a 좌표계에서 본 자세다. 그래서 `T_a_c = T_a_b @ T_b_c`처럼 가운데 글자가 맞물린다. 쿼터니언과 오일러 각은 MuJoCo, URDF, 사람이 보는 값 같은 경계에서만 쓴다.
- **좌표계**: 오른손 좌표계다. 베이스 좌표계는 설치면 중심에서 z가 위, x가 작업대 쪽이다. 플랜지 좌표계는 z가 플랜지 면에서 도구 쪽이다. 관절의 양의 방향은 관절 축에 대한 오른손 법칙이다.
- **링크 좌표계**: 영점 자세에서 모든 링크 좌표계의 방향을 베이스 좌표계와 같게 둔다. 관절 원점은 부모 링크 좌표계에서 위치만 주고, 관절 축은 단위 벡터로 준다. 회전이 있는 좌표계는 플랜지와 TCP 같은 고정 좌표계뿐이다.
- **이름**: 관절 `j1`~`j6`, 바디 `base`, `link1`~`link6`, 사이트 `flange`, `tcp`. MJCF, URDF, 로봇 설정, 메시지에서 같은 이름을 쓴다. 그리퍼는 붙일 때 그리퍼 이름을 접두어로 붙인다.
- PEP 8을 따르고 이름은 영어로 쓴다. 공개 함수에는 타입 힌트를 단다.
- 주석과 docstring은 한국어로 쓰고, 코드만 봐서는 모를 "왜"를 쓴다.
- 파일은 UTF-8로 열고, 경로는 `pathlib`으로 다룬다.
- 출력은 `logging`을 쓴다. 명령줄 도구가 결과를 보여 주는 출력은 `print`로 해도 된다.
- 결정 기록에 쓰는 계산 결과는 검토 코드로 다시 만들 수 있게 하고, 기록에 실행 명령을 적는다.
- 포맷과 린트는 ruff, 타입 검사는 pyright(standard 모드, servo 패키지는 strict 모드)다.
- Rust: 이름과 포맷은 Rust 관례(rustfmt)를 따르고, 단위와 이름 규칙은 위와 같다. 주석과 문서 주석은 한국어로 쓴다.
- Rust의 린트는 clippy이고 경고도 실패로 본다. unsafe는 워크스페이스에서 막아 두고, 꼭 필요한 곳만 이유를 적어 연다.
- Rust 오류는 `Result`로 돌려준다. 실물을 움직이는 코드에서는 `unwrap`, `expect`로 프로그램을 끝내지 않는다.

## 테스트

- pytest를 쓴다. 테스트는 패키지마다 `packages/<이름>/tests/`에 두고, 패키지를 넘나드는 검사(의존 방향 등)와 패키지 밖 도구(`tools/`)의 테스트는 루트 `tests/`에 둔다.
- 표시는 없음(빠른 것), `slow`(CAD 생성처럼 느린 것), `hardware`(실물 서보·카메라)다. 기본 실행은 `hardware`를 뺀 전부다. `hardware`는 `--hardware`를 줘야 돌고, Claude는 확인을 받은 뒤에만 돌린다. 실물 백엔드는 `hardware` 테스트에서만 만든다.
- Rust 테스트는 `cargo test`로 돈다. 단위 테스트는 모듈 안(`#[cfg(test)]`)에, 여러 모듈을 묶는 테스트는 `crates/<이름>/tests/`에 둔다.
- 패키지와 크레이트 사이의 의존 방향은 `tests/test_structure.py`가 확인한다.
- 커밋 전에 포맷, 린트, 타입, 테스트를 돌린다. 명령은 [CLAUDE.md](../CLAUDE.md#자주-쓰는-명령)에 있다. CI는 두지 않는다.

## git

- 커밋은 너무 잘게 쪼개지 않고, 의미 있는 단계가 끝날 때 한다.
- 브랜치는 main 하나에 커밋하고, 위험한 실험만 짧은 브랜치에서 한다.
- push는 확인을 받은 뒤에 한다.
- 커밋 메시지는 한국어로 쓴다. 첫 줄에 바뀐 것을 요약하고, 자세한 건 빈 줄 다음에 쓴다. Claude가 쓴 커밋에는 `Co-Authored-By` 줄을 단다.
- 줄바꿈은 LF다 (`.gitattributes`).
- 라이선스는 MIT다 ([LICENSE](../LICENSE)).
