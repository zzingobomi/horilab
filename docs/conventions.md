## 문서

### 어디에 쓰나

| 위치 | 담는 것 |
|---|---|
| README.md | 이 레포가 무엇인지, 지금 상태 한 줄, 문서 목록 |
| CLAUDE.md | 새 세션이 먼저 읽을 문서, 작업 규칙, 자주 쓰는 명령. 짧게 쓰고 자세한 건 링크한다 |
| docs/ | 실제 내용 전부. 주제마다 파일 하나로 시작하고, 커지면 그 주제만 폴더로 나눈다 |
| docs/decisions/ | 결정 기록 |
| docs-local/ | 공개하지 않는 개인 자료. git에서 제외한다. 이 폴더가 없는 PC에서도 작업이 이어져야 하므로, 작업에 꼭 필요한 정보는 여기에 두지 않는다 |

다른 프로젝트가 레포에 들어오면 팔 전용 문서(goals, background, hardware, design, manufacturing, software)는 docs/<프로젝트 이름>/ 아래로 옮기고, 나머지는 공통 문서로 둔다.

### 쓰는 법

- 본문은 한국어, 파일 이름은 영어로 쓴다.
- 결정, 근거, 사실만 쓴다. 대화 내용을 옮기거나 개인에 대한 서술을 넣지 않는다. 공개하기 애매한 내용은 docs-local/에 둔다.
- 정보는 한 곳에만 쓰고 다른 곳에서는 링크한다. 주제 문서에는 지금 어떻게 돼 있는지만 쓰고, 이유는 결정 기록으로 링크한다.
- 수치에는 단위를 붙인다.
- status.md는 지금 상태만 짧게 유지하고, 작업 단위가 끝나면 고친다. 지난 일은 git 기록과 결정 기록에 남는다.

### 결정 기록

- 고민이 필요한 결정은 하나마다 파일 하나로 남긴다: `docs/decisions/NNNN-영어-제목.md`. 당연한 관례는 기록하지 않는다.
- 상태는 제안, 채택, 대체됨 중 하나다.
- 결정을 조정할 때(순서, 라이브러리, 세부 값)는 그 기록을 고치고, 맨 아래 "바뀐 점"에 날짜와 무엇을 왜 바꿨는지 한 줄로 남긴다. 이전 내용은 git 기록에 있다. 오타나 다른 문서와 맞추는 고침은 그냥 고친다.
- 결정을 뒤집을 때만 새 기록을 쓰고, 옛 기록의 상태를 "대체됨 (NNNN)"으로 바꾼다. 주제마다 지금 유효한 기록이 하나만 있게 하려는 것이다.
- 여러 갈래를 한 번에 정할 때는 대안 비교를 표로 묶어도 된다.
- 양식:

```markdown
# NNNN. 제목

- 상태: 채택
- 날짜: YYYY-MM-DD

## 배경
무엇을 왜 정해야 했나.

## 검토한 대안
대안마다 장점과 단점.

## 결정
무엇으로 정했나.

## 근거
왜 그 대안인가.

## 영향
이 결정으로 생기는 것, 나중에 다시 볼 조건.

## 바뀐 점 (조정한 적이 있을 때만)
- YYYY-MM-DD: 무엇을 왜 바꿨나.
```
